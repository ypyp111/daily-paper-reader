## 摘要
昇腾C算子优化对NPU（神经处理单元）推理性能至关重要，但需要深厚的硬件专业知识。尽管大型语言模型（LLM）在自动CUDA内核生成方面展现出潜力，但昇腾C编程模型的根本差异带来了尚未探索的独特挑战。本文提出AgenticCANN，一种知识增强的智能体演化框架，专门针对低语料NPU环境下的自动昇腾C算子合成。为克服不熟悉硬件上的严重平台知识缺陷，AgenticCANN引入了知识编排生成系统，在开发生命周期中提供结构化、多层次的领域洞察，以解决上游可行性瓶颈。在此基础上，其具备阶段自适应的智能体演化策略，动态地将LLM交互模式与特定生成和演化阶段对齐，平衡高探索性候选发现与高收敛性性能调优。在华为昇腾910B上覆盖五种模式类别、六个算子的广泛实验表明，我们的方法在逐元素和归一化算子上的可行性达到90%至100%，融合算子为56%，在1B盘古模型推理内核上实现最高6.65倍加速。进一步分析显示，知识注入将逐元素算子的可行性从57%单调提升至86%，证明其具有普适性而非算子特定性的收益。

## Abstract
Ascend C operator optimization is critical for NPU (Neural Processing Unit) inference performance but requires deep hardware expertise.While large language models (LLMs) have shown promise in automated CUDA kernel generation, the fundamentally different programming model of Ascend C introduces unique challenges that remain unexplored. In this paper, we propose AgenticCANN, a knowledge-augmented agentic evolution framework specifically tailored for automated Ascend C operator synthesis in low-corpus NPU environments.To overcome the severe platform knowledge deficit on unfamiliar hardware, AgenticCANN incorporates a knowledge-orchestrated generation system that delivers structured, multi-level domain insights across the development lifecycle to resolve the upstream feasibility bottleneck.Building on this foundation, it features a stage-adaptive agentic evolution strategy that dynamically aligns LLM interaction modes with specific generation and evolution phases, balancing high-exploration candidate discovery with high-convergence performance tuning.Extensive experiments on Huawei Ascend 910B across six operators spanning five pattern categories demonstrate that our method achieves 90 to 100 percent feasibility on elementwise and normalization operators, 56% on fusion operators, and up to 6.65$\times$ speedup on 1B Pangu model inference kernels. Further analysis reveals that knowledge injection monotonically improves feasibility from 57% to 86% on elementwise operators, demonstrating its general rather than operator-specific benefit.

## 1. 核心问题与研究背景

论文聚焦于 **昇腾 C（Ascend C）算子的自动化生成与优化**。其核心动机与挑战如下：

- **背景冲突**：昇腾 NPU（华为 Ascend 910B）已成为 NVIDIA GPU 之外的重要推理基础设施，其编程模型 Ascend C 基于 CANN 工具包，采用**显式数据流架构**（统一缓冲区 UB 分块、TQue 乒乓缓冲队列、显式同步），与 CUDA 的细粒度线程/线程束模型有本质区别。
- **关键瓶颈并非性能调优，而是上游可行性**：CUDA 内核自动生成（如 EvoEngineer、KernelBench）依赖 LLM 预训练语料中丰富的开源 CUDA 代码。而昇腾 C 是**严重低语料（low-corpus）领域**，LLM 几乎无法生成一个可编译的非平凡算子。作者形式化地指出：在没有外部知识注入时，\(P_{LLM}(C(x)=1 | O) \approx 0\)，即非逐元素算子编译成功概率趋近于零。

  1. **封闭世界假设崩塌**：EoH、EvoEngineer 等依赖预训练分布内的启发式变异，在昇腾 C 上无法解释编译器反馈，陷入永久编译失败循环。
  2. **单一交互模式不匹配**：将同一种智能体模式应用于整个演化过程，面临**探索（exploration）与收敛（convergence）之间的内在冲突**。

**整体含义**：论文试图回答一个根本问题——在极端数据匮乏下，LLM 能否在陌生硬件平台上实现代码合成的可行性？其答案是通过结构化知识注入与阶段自适应智能体调度来弥补预训练分布缺失。

## 2. 方法论：AgenticCANN 框架

AgenticCANN 是一个两阶段（生成 + 演化）的闭环框架，由三个紧密耦合的模块组成：**知识层**、**生成与演化层**、**评估层**。核心机制如下：

### 2.1 知识编排生成（Knowledge-Orchestrated Generation）

- **六层认知知识分类法（L0–L5）**：
  - L0：编程模型（pipeline、TQue、UB 内存）——建立硬件心智模型；
  - L1：模式指南（映射规则、张量布局）——桥接数学语义到代码；
  - L2：硬件约束（UB 限制、32 字节对齐、缓冲区配对）——执行不变量；
  - L3：分块策略（tiling 公式、尾部处理）——指导内存带宽利用；
  - L4：API 参考（向量指令签名）——确保语法有效性；
  - L5：已验证的示例内核代码——提供结构脚手架。

- **阶段差异化装配（Phase-Differentiated Assembly）**：不同演化阶段只注入相关的知识层级。初始化注入全量 L0–L5；变异阶段仅保留 L2–L4 紧凑护栏；编译修复侧重 L2+L4；性能调优仅用 L3。这使提示词从初始化的约 800 tokens 降至性能调优阶段不足 100 tokens，**降低 8 倍每代成本**。

- **模式路由（Pattern-Based Routing）**：将算子分为 elementwise、reduction、softmax、broadcast、normalization、matmul、convolution、attention、index、pooling、resize、fusion 等类别，每类映射专属知识资产，支持新算子只需添加知识资产。

### 2.2 阶段自适应智能体演化（Stage-Adaptive Evolution）

论文定义了三种交互原语，构成能力谱系：

| 模式 | 工具 | 反馈来源 | 探索能力 | 收敛稳定性 |
|------|------|----------|----------|------------|
| Single-Pass | 无 | 无 | 低 | 高 |
| Fix-Loop | 无 | 日志 + 上下文 | 中 | 中 |
| Tool-Agent | 读/编辑/编译 | 执行轨迹 | 高 | 低 |

**调度策略**：初始化阶段（g=1）使用高探索模式（Tool-Agent 或 Fix-Loop）建立有效候选种子；后续代（g>1）切换至高收敛模式（Single-Pass 或轻量 Fix-Loop）进行结构保持的优化。实验显示（GELU）阶段自适应实现 **+26.0% 提升，仅消耗 350K tokens**，而单调 Tool-Agent 仅 +0.04% 却消耗 4.18M tokens。

1. **知识注入解锁可行性**：LayerNorm 从 0% 可行性单调提升至 90%（L0→40%，+L2→60%，+L5→80%，全量→90%），速度提升达 2.71 倍。

3. **知识注入具有普适性**：14 个逐元素算子上，可行性从 57%（Free）→71%（Insight）→86%（Full），平均延迟从 741.3μs 降至 711.0μs；各算子均有一致改善（hardtanh -18.4%、softplus -15.2%）。

## 8. 不足与局限

- **模型泛化未验证**：主要使用 DeepSeek-V4 系列模型，未在 Qwen2.5-Coder、Llama-3、GPT-4o 等多模型家族上做交叉验证，知识注入收益是否模型无关仍未确认。

- **Transformer 完整算子覆盖待完善**：注意力与卷积拓扑尚未实现端到端生成，限制了框架对现代模型架构的完整适用性。
