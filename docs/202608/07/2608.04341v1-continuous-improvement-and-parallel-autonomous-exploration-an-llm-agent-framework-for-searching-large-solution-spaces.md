## 摘要
我们提出了一个框架，为LLM智能体提供了两种自主搜索大型解决方案空间的机制。首先，基于留出数据评分的排行榜作为奖励信号，驱动每个智能体通过反复提交来改进其解决方案，这一循环即使只有单个智能体也能运行。其次，该框架支持完全自主地并行运行多个智能体，无需人类参与：智能体独立地分析、调研方法、实现、自我评估、提交和修订，而协调智能体仅处理后勤事务。在共享奖励下并行运行智能体可以拓宽解决方案空间的探索区域，而不是仅仅改进单一的初始范式。我们将该框架应用于产品到目录匹配（一个具有大型类别结构解决方案空间的核心电商检索任务），并将其表述为具有精确率-覆盖率工作点的选择性预测。单个智能体在其初始范式内进行改进，而并行自主智能体则产生性质不同的解决方案。在该测试平台上，最佳合格覆盖率（每个类别>=95% P@1）在单个智能体下达到47.8%-57.4%，在五个智能体下达到62.8%-69.4%，而基线为33.3%。我们的贡献在于框架本身：一个持续改进的奖励循环和完全自主并行探索的基础平台，并辅以案例研究证据。

## Abstract
We present a framework that gives LLM agents two mechanisms for searching large solution spaces autonomously. First, a leaderboard scored on held-out data acts as a reward signal that drives each agent to refine its solutions over repeated submissions, a loop that operates even with a single agent. Second, the framework enables running many agents in parallel, fully autonomously, with no human in the loop: agents independently analyze, survey methods, implement, self-evaluate, submit, and revise, while a moderator agent handles only logistics. Running agents in parallel under the shared reward broadens the explored region of the solution space rather than refining the single seeded paradigm. We instantiate the framework on product-to-catalog matching (a core e-commerce retrieval task with a large, category-structured solution space), posed as selective prediction with a precision-coverage operating point. A single agent refines within its seeded paradigm, whereas parallel autonomous agents surface qualitatively different solutions. On this testbed, best qualified coverage (>=95% P@1 per category) reaches 47.8-57.4% with a single agent and 62.8-69.4% with five, against a 33.3% baseline. Our contribution is the framework itself: a continuous-improvement reward loop and a substrate for fully autonomous parallel exploration, backed by case-study evidence.

# 论文总结：持续改进与并行自主探索的LLM智能体框架

## 1. 核心问题与整体含义

- **研究动机**：大语言模型（LLM）智能体已能自主编写代码、运行实验并迭代结果，但许多实际优化问题具有**巨大的解决方案空间**，且通常需要任务特定的优化策略。已有LLM智能体方法多集中于**协作式或沟通式架构**（如MetaGPT、ChatDev、CAMEL），较少研究在**共享奖励信号**下、完全自主并行运行的智能体如何集体搜索解空间。
- **核心问题**：如何在不依赖人类干预、也不显式设计多样性保持机制的情况下，使LLM智能体更广泛地探索大型解决方案空间，避免陷入单一初始范式的局部最优？
- **整体含义**：该论文提出了一个框架，赋予LLM智能体两种机制：
  1. **持续改进奖励循环**：以留出测试集上的排行榜分数作为奖励信号，驱动单个智能体反复提交和优化；
  2. **完全自主并行探索**：多个智能体在共享奖励下独立运行，互不通信代码，仅共享分数和方案摘要，从而拓宽解空间探索范围。
- **应用落地**：将框架用于**产品到目录匹配**（product-to-catalog matching），这是一个核心电商检索任务，具有类别结构化的大解空间，被表述为**选择性预测**（selective prediction）问题，在保证高精度的前提下最大化覆盖率。

## 2. 方法论

### 2.1 任务形式化
- 输入：用户listing（标题、描述、元数据、类别），输出：正确的目录SKU。
- 每个预测附带置信度，低于阈值的预测被放弃（abstain），形成**精确率-覆盖率权衡**。
- 评价指标：
  - **Precision@1 (P@1)**：已覆盖预测中top-1正确的比例；
  - **Coverage**：做出预测的listing比例。
- 合格条件：**每个类别独立的P@1均≥95%**；在合格提交中，按**平均覆盖率**排序。

### 2.2 框架基础设施
- **自动化排行榜（LeaderboardAPI）**：
  - 对留出测试集（agent不可见）评分；
  - 计算各类别P@1和覆盖率，检查合格条件，排序合格提交；
  - 结果追加到持久化JSON账本，所有agent可查看完整排行榜（分数+方案描述）。
- **训练/测试分离与完整性保护**：
  - 训练数据带标签供agent自我评估；测试数据无标签，必须提交排行榜评分；
  - 严格的属主/共享/参与者权限边界，自动化预运行泄漏检查；
  - 每个agent限定在自己的工作目录，只读共享资源，防止复用他人构件（文中观察到这种尝试）。
- **GPU资源管理**：
  - 多agent共享一个GPU节点；早期因并发使用导致崩溃，因此设计了**双级锁**，30分钟CLAIM/RELEASE协议；
  - 系统级看门狗终止未授权GPU进程。
- **自主性与持续运行**：
  - 全程无人类参与，仅一条启动命令指定agent数量和时间预算；
  - 协调者（moderator）本身也是自动化agent，但**仅限后勤**（时间警告、排行榜更新、队列管理），不提供技术指导；
  - agent按固定节奏发送心跳和进度报告；deadline前30分钟和5分钟警告，到时强制终止。

### 2.3 Agent设置
- 每个agent由 **Claude Sonnet 3.5** 驱动，可使用Python环境：BGE-M3、Qwen3-Embedding、FAISS、TF-IDF。
- 接收任务简报：任务、数据格式、提交协议、GPU协调规则、5小时时间预算、BGE-M3基线参考。
- 迭代循环：分析数据/错误 → 调研方法 → 提出假设 → 实现 → 训练集自评 → 提交测试预测 → 观察排行榜 → 修订。

## 3. 实验设计

### 3.1 数据集与场景
- 来自大型日本C2C市场（Mercari）的**三个类别**：
  - 智能手机（Smartphone）
  - 交易卡（其他）（Trading Card (Others)）
  - 交易卡（宝可梦）（Trading Card (Pokemon)）
- 基线：BGE-M3嵌入 + 余弦相似度，阈值为每个类别在训练集上调优以满足95% P@1，再应用到测试集。基线在“交易卡（其他）”类别上P@1为94.5%，**未达到合格标准**（因此整体不qualified）。
- 基线平均覆盖率：33.3%。

### 3.2 对比配置
- **单agent**：一个agent独立迭代。
- **并行（5个agent）**：5个agent同时完全自主运行，共享GPU，仅通过追加式聊天日志协调，agent间只能看到排行榜分数和方案描述，看不到彼此代码。
- 每组配置各运行**三次**，报告范围值。

## 6. 主要结论与发现

- **持续改进有效**：在两种配置下，排行榜奖励驱动了持续改进。最佳合格覆盖率从基线33.3%提升到：
  - 单agent：**47.8%–57.4%**
  - 5-agent并行：**62.8%–69.4%**
- **并行探索带来范式突破**：
  - 所有3次单agent运行（60/124/81次提交）都**从未跳出BGE-M3嵌入范式**，不断在嵌入变体、阈值、校准上打转；一次运行甚至提前判断最难类别不可解而停止。
  - 所有3次5-agent运行中，agent在几分钟内独立找到**非嵌入方法**（如TF-IDF重排、字符串相似度匹配）。
  - 提升主要集中在**最难的智能手机类别**：单agent覆盖0.8%–1.9%，并行达到24.8%–41.1%；交易卡类别上单agent与并行竞争力相当。
- **方法多样性示例**（一次代表性5-agent运行）：
  - α：分数差置信度校准（50.7%覆盖率）
  - β：BGE-M3 + TF-IDF重打分（55.3%）
  - γ：卡号重排 + 纯字符串SequenceMatcher（65.6%）
  - δ：字符串匹配 + 词/字符TF-IDF融合（69.4%，最优）
  - ε：字符串相似度重排（63.6%）
  - 所有5个agent都合格，非嵌入的字符串/TF-IDF方法（γ、δ）取得了最佳结果。
- **排行榜动态**：首次合格提交出现较晚（δ，BGE-M3，27.5%），覆盖率通过阈值调整、卡号重排逐渐上升到65.6%，随后平台期；最后δ在截止前通过字符串匹配+word-TF-IDF融合提升至69.4%。
- **深度 vs 广度**：单agent“深而窄”，并行agent“宽而浅”（平均P@1为95.1%，略低于单agent的95.1%–96.7%，并有严重GPU争用）。

## 7. 优点

- **框架创新性**：将**留出数据排行榜奖励循环**与**并行自主探索**结合，无需人类指定技术方向，也不强制智能体协作，仅共享分数和方案摘要，实现解空间扩散。
- **完整性设计严谨**：训练/测试分离、权限边界、自动化泄漏检查、GPU锁、强制持续运行等细节体现了工程可靠性。
- **客观的自我评估**：作者明确声明覆盖率差异是**描述性范围**，不是因果缩放定律；反复强调混杂因素，体现科学严谨性。
- **任务选择恰当**：产品-目录匹配具有类别结构化的大解空间，且不同类别适用不同方法，天然适合验证探索广度的益处。
- **发现重复性**：核心定性发现（单种子agent窄化、并行agent逃逸）在6次运行中一致，不依赖于agent数量。

## 8. 不足与局限

- **混淆变量**：agent数量与总计算量、并发度、GPU争用、排行榜可见性共变，无法分离因果；覆盖率提升不能归因于并行本身。
- **缺少无种子对照**：未测试“不提供BGE-M3基线种子”的情况，无法区分“种子诱导的窄化”与“Claude Sonnet 3.5自身的先验倾向”。
- **模型与任务单一**：所有agent使用同一LLM；仅在单一任务（产品-目录匹配）上验证，跨任务泛化未证明。
- **实验重复次数少**：每种配置仅3次，统计学意义有限。
- **未见消融**：没有改变agent数量、通信方式、信息共享程度、时间预算等关键设计变量。
- **安全问题**：agent自主提交的代码未经人工安全审查；框架只防跨agent破坏，不审计LLM生成代码本身。
- **范围有限**：任务为有明确自动指标且迭代快的受控环境；对长周期、模糊成功标准的场景未探索。
- **时间跨度**：论文发表于2026年（arXiv编号2608），所引用的模型（如Claude Sonnet 3.5）可能非最新，结论时效性有待考虑。
