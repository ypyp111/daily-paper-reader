## 摘要
工具调用使大型语言模型（LLM）能够在问题求解过程中调用外部计算，这一能力在包括数学AI在内的多个领域中十分有用。我们通过加权平方和（SOS）分解这一研究设置来探讨该能力，这是一种通过机器可验证途径证明多项式非负性乃至多项式不等式的方法。候选分解可以被精确验证，但找到它需要在非唯一的重新分组中进行选择，并协调多个符号变换。我们开发了一个智能体，它将代数任务训练、符号工具和基于验证器的优化相结合以完成该任务。我们不仅在复合SOS任务上进行训练，还构建了135万个涵盖八个支持性多项式任务以及加权SOS分解的合成示例。我们首先应用监督微调（SFT）来处理直接的代数问题和模拟符号轨迹，然后使用带有任务特定符号奖励的组相对策略优化（GRPO）。SFT语料库中不包含原生工具调用消息；在评估时，智能体使用原生SymPy调用来进行展开、收集、重排序和因式分解。每个最终的SOS答案都通过精确展开和系数比较进行验证。在保留的同生成器合成问题上，完整的SFT+GRPO+工具系统是四种评估配置中最强的，在加权SOS上达到78.96%的验证成功率，而使用相同工具的基础模型为44.73%，在九个多项式任务上的宏观准确率达到91.75%。在这一受控设置中，我们的工作提供了一个结合领域特定技能训练、可执行工具和验证器反馈的案例研究，并可能为其他具有可精确验证输出的领域中工具调用智能体的设计提供参考。

## Abstract
Tool calling allows large language models (LLMs) to invoke external computation during problem solving, a useful capability in various fields including AI for mathematics. We study this setting through weighted sum-of-squares (SOS) decomposition, a machine-checkable route to proving polynomial nonnegativity and hence polynomial inequalities. A candidate decomposition can be checked exactly, but finding one requires choosing among non-unique regroupings and coordinating multiple symbolic transformations. We develop an agent that combines algebraic task training, symbolic tools, and verifier-grounded optimization for this task. Rather than training only on the composite SOS task, we construct 1.35 million synthetic examples covering eight supporting polynomial tasks together with weighted-SOS decomposition. We first apply supervised fine-tuning (SFT) to direct algebra problems and simulated symbolic traces, and then use Group Relative Policy Optimization (GRPO) with task-specific symbolic rewards. The SFT corpus contains no native tool-calling messages; at evaluation, the agent uses native SymPy calls for expansion, collection, reordering, and factorization. Every final SOS answer is checked by exact expansion and coefficient comparison. On held-out, same-generator synthetic problems, the full SFT+GRPO+tools system is the strongest of four evaluated configurations, reaching 78.96% verified success on weighted SOS, compared with 44.73% for the base model with the same tools, and 91.75% macro accuracy across nine polynomial tasks. Within this controlled setting, our work provides a case study of combining domain-specific skill training, executable tools, and verifier feedback, and may inform the design of tool-calling agents in other domains with exactly checkable outputs.

## 1. 核心问题与研究动机

本论文旨在回答一个核心问题：

> **能否通过代数基础训练（algebra-grounded post-training）使 LLM 学会协调精确的符号操作（即多步符号搜索），而非仅仅执行孤立的代数变换？**

这一问题的背景是：尽管外部符号工具（如 SymPy）可以保证局部运算的可靠性，但工具使用型 LLM 仍需自行判断哪些操作有用、如何构造参数、如何解读观测结果、怎样从无效分支中恢复、以及何时停止。这类"协调决策"在输出易于验证但难以搜索的任务中尤为凸显——加权 SOS 分解恰好是这类任务的理想载体。

**加权SOS（sum-of-squares）任务的定义**：寻找形如 \(f = \sum_{j=1}^{m} c_j p_j^2,\; c_j \in \mathbb{Q}_{>0}\) 的恒等式，它能够证明多项式 \(f\) 的全局非负性，且验证一个候选恒等式的代价极低（精确展开+系数比较），但搜索该恒等式的过程是**非唯一的、需要策略性的**：展开会隐藏平方结构，混合项有多种可能的分组方式，局部正确的变换可能留下无用的余项。

## 2. 方法论

### 2.1 总体架构

该方法将训练与部署明确分为两个阶段，构建"**任务训练 → 模拟轨迹 SFT → 验证器驱动的 GRPO → 原生工具部署**"的完整管线（如图1所示）。

### 2.2 九任务课程设计

构建了涵盖九个多项式任务的合成课程（每任务 150,000 条样本，共 135 万条，5% 验证集，128.25 万条训练记录）：

| 类别 | 任务 | 描述 |
|------|------|------|
| **局部操作**（工具对齐） | 词典序项排列 | 按指定变量次序规范化多项式 |
| | 收集（Collection） | 按指定变量/表达式整理系数 |
| | 展开（Expansion） | 完全展开多项式 |
| | 因式分解 | 输出乘积表示 |
| **结构代数**（更广表征） | Horner 形式 | 递归嵌套结构 |
| | 对称约化 | 基本对称多项式基表示 |
| | 商/余数 | 精确满足 \(f=qg+r\) 且余式不可再除 |
| | 扩展 GCD | 一元情况下的 Bézout 恒等式 |
| **复合目标任务** | 加权 SOS 分解 | 需要调用符号工具进行多步搜索 |

**关键设计**：八个支持任务在训练和评估时**均不涉及原生工具调用**；原生工具调用仅在加权 SOS 评估阶段使用。SFT 语料中的 SOS 轨迹用"Python 风格代码片段+返回结果"模拟符号计算，但**不包含原生 function-call 消息或工具描述**。

### 2.3 训练管线

**(1) 监督微调（SFT）**
- 使用 **4-bit QLoRA** 微调 `Phi-4-reasoning-plus`
- 仅 assistant token 参与损失计算（system/user 作为上下文被 mask）
- rank=32, scale=16, dropout=0.05, LR=5×10⁻⁵，单 epoch
- 181,848 条 packed 序列，约 3.72×10⁸ tokens，22,731 优化步

**(2) 验证器驱动 GRPO**
- 从 SFT 模型出发，使用任务特定符号奖励优化采样响应
- 奖励函数形式：\(R_k(y) = -1\)（格式错误）或 \(0.1 I_{\text{fmt}}(y) + 0.9 r_k(y)\)
- 每个任务 \(r_k \in [0,1]\) 由**精确任务契约**而非字符串匹配计算（如商/余数通过 \(f=qg+r\) 和余式可约性检验；SOS 奖励以可解析的加权平方结构和系数残差为门控）
- 工具轨迹塑形奖励：奖励 schema 有效调用和成功执行，惩罚重复调用和过长轨迹，给终验证最大的激励
- GRPO 超参数：全局 prompt batch=64，每 prompt 8 个生成，20,039 优化步

**(3) 原生部署**
- 加权 SOS 评估时暴露四个 SymPy 函数：`expand_polynomial`, `collect_terms`, `reorder_polynomial`, `factorize_polynomial`
- 预算限制：最多 10 次调用、3 次分解尝试、每次调用 5 秒、每 episode 60 秒
- 终端验证器要求解析为 \(f = \sum c_j p_j^2\) 且 \(\text{expand}(f - \sum c_j p_j^2) = 0\) 精确成立

## 6. 主要结论

1. **精确执行并不能消除协调错误**：Base+Tools 仅 44.73% 验证成功率证明了这一点——工具可以完美执行被请求的操作，但智能体仍会选错操作、参数、分组或停止点。终端失败分为三类：提前完成/弃权、结构无效的加权 SOS、结构有效但展开不匹配。

2. **代数基础训练是工具访问的有效补充**：Full 比 Base+Tools 高 34.23pts，表明训练工具背后的操作和表征（而非仅仅学习接口）是关键。

3. **改进幅度与任务复杂度相关**：Full 相对 SFT 的增益按 局部操作（+12.46pts）→ 结构代数（+18.08pts）→ 加权 SOS（+27.14pts）递增——需要更多全局表征和搜索选择的任务收益更大。

4. **发现、交互和验证必须分开**：成功率达到 78.96% 是"在固定预算下的证书搜索产量"，不是 SOS 识别率；Schema 合法的调用或成功的后端执行只是中间事件，不构成证明。

## 7. 方法优点

- **验证器与训练目标强一致**：SOS 奖励以精确结构门控和系数残差为准，先验奖励仅占 0.1 权重；GRPO 将策略优化锚定在"代数状态"而非单一参考轨迹，允许多个不同但正确的分解都被认可。

- **精心设计的合成数据生成器**：支持任务采用前向变换（确定性的符号操作）与逆向构造（代数关系任务）互补模式；SOS 生成器从隐藏证书反向展开，任何满足恒等式的有效分解均可被接受，避免了对单一答案路径的偏置。

- **训练-部署边界清晰**：SFT 语料无原生函数调用消息 → SOS 部署使用原生工具调用，这一有意的错位迫使模型学习运算的"语义"而非"语法模板"。

- **验证的严格性**：终端验证器要求结构可解析、权重为正有理数、且展开恒等式精确成立（系数逐一比较），杜绝了形式化不够导致的虚假证明。

- **诚实的实验声明**：论文多处明确区分了"完整系统比较"与"因果组件效应"、区分直接任务评估与部署环境评估、区分系统宏观指标与均匀检查点指标，学术诚实性高。

- **保留检查的合理设计**：用 AIME 和 GSM-8K 检验代数专项训练没有付出过大的通用能力代价。

## 8. 不足与局限

### 实验覆盖局限
- **问题范围有限**：仅 1–3 个变量、度为 2/4/6 的加权 SOS；不覆盖自然不等式基准（如 Olympiad 级不等式）、大规模多项式、非 SOS 分类或约束证书（如 Putinar/Schmüdgen 形式）
- **同分布评估**：训练与测试共享生成器族，仅衡量设计环境内的能力，不能推断 OOD 泛化
- **单背骨、单次运行**：无跨背骨（如其他 LLM）验证，无训练运行间方差估计；Wilson 区间仅量化测试集采样噪音

### 设计局限
- **非因子化对比**：未评估 SFT+Tools（无 GRPO）和 GRPO（无工具）两个条件，无法将 GRPO vs SFT 或工具接入 vs 训练阶段的效果因果分明
- **整体系统 vs. 模型归因**：轨迹级结果属于完整的"模型-框架"系统；将每次分组、重试或停止决策精确归因于 LM 本身是不可能的
- **奖励组合未消融**：工具轨迹塑形项与任务分数是联合评估的，单项贡献未被隔离
- **验证器不如证明助手强**：仅验证正有理权重、平方结构和系数恒等式，不形式化侧假设或约束 Positivstellensatz 论证

### 外部有效性与应用限制
- 算术复杂度低（系数 [-10,10]，项数 ≤5），真实世界的多项式问题通常远更复杂
- 方法的实际意义被定位为"工具协调能力的研究平台"，而非 SOTA 不等式证明器
