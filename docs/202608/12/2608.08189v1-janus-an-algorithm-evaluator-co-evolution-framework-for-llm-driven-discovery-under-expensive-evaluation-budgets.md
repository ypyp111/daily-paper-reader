## 摘要
大语言模型驱动的程序发现依赖于快速的评估器反馈，但许多科学与工程任务需要高保真模拟、硬件执行或物理实验，这使得每次评估代价高昂。廉价的代理评估器可以降低这一成本，但固定的代理评估器容易受到搜索引起的分布偏移的影响，并且难以从稀疏、搜索偏倚的标签中可靠地拟合。我们提出了Janus，一个利用大语言模型协同进化目标程序和可执行代理评估器的框架。为解决标签稀缺问题，Janus利用大语言模型中编码的领域知识生成特定任务的评估器程序，并使用真实结果对其进行校准。为缓解分布偏移，Janus将评估器与目标程序一同进化，使用与提升对齐的目标进行选择，并维护具有在线信用更新的区域条件组合。由于代理预测仍可能出错，Janus仅将其用于候选排序，并要求候选者进入目标程序群体或更新当前最优解之前必须经过真实验证。在五个科学与工程设计任务中，与仅进化目标程序的匹配基线相比，Janus在真实评估预算下的最佳改进曲线面积更大，最终性能也更高。平均而言，Janus以59.1%更少的真实评估次数达到了基线最终改进的99%。进化后的代理评估器对候选者的排序也较其初始版本更准确。这些结果共同将评估器引导的大语言模型发现从具有廉价、可扩展反馈的任务扩展到可信评估稀缺且昂贵的科学领域。

## Abstract
LLM-driven program discovery relies on rapid evaluator feedback, but many scientific and engineering tasks require high-fidelity simulations, hardware execution, or physical experiments, making each evaluation expensive. Cheap surrogate evaluators can reduce this cost, yet fixed surrogates are vulnerable to search-induced distribution shift and are difficult to fit reliably from sparse, search-biased labels. We introduce Janus, a framework that uses LLMs to co-evolve target programs and executable proxy evaluators. To address label scarcity, Janus leverages domain knowledge encoded in LLMs to generate task-specific evaluator programs and calibrates them using real outcomes. To mitigate distribution shift, Janus evolves evaluators alongside target programs, selects them using a promotion-aligned objective, and maintains region-conditioned portfolios with online credit updates. Because proxy predictions remain fallible, Janus uses them only to prioritize candidates and requires real validation before candidates can enter the target-program population or update the incumbent. Across five scientific and engineering design tasks, Janus achieves a larger area under the best-so-far improvement curve over the real-evaluation budget and higher final performance than a matched baseline that evolves only target programs. On average, Janus reaches 99/% of the baseline's final improvement with 59.1/% fewer real evaluations. Evolved proxy evaluators also rank promising candidates more accurately than their seed versions. Together, these results extend evaluator-guided LLM discovery from tasks with cheap, scalable feedback to scientific domains where trustworthy evaluation is scarce and expensive.

- **背景**：LLM驱动的程序发现（如FunSearch、AlphaEvolve）通过"提案-评估-反馈"循环,在数学、算法等领域取得了显著成功。其核心前提是**评估器（evaluator）廉价且反馈快速**（例如，矩阵乘法中乘法次数的计数）。
- **核心问题**：许多科学与工程任务（如电池充电协议设计、网络拥塞控制、光子器件设计、化学反应控制、库存路由优化）的**真实评估代价极高**——需要高保真模拟、硬件执行或物理实验，一次评估可能耗时数小时甚至数天。在这种条件下，评估每个候选程序是不现实的，**真实评估预算取代候选生成，成为主要瓶颈**。
- **现有方案的局限**：
    - 训练廉价代理评估器（surrogate）是常见思路，但面临两大挑战：
        - **分布偏移**：搜索过程受代理预测引导，候选分布会漂移出代理训练数据支持的区域，导致预测误差累积，误导后续搜索。
        - **标签稀缺**：真实评估数量有限且由搜索过程选择，导致可用的训练数据既稀疏又存在偏差。传统代理模型（如GP、随机森林、MLP）难以从如此数据中捕捉科学问题中不同区域间发生的**机制性变化**（如网络从低延迟到拥塞的突变）。
- **整体含义**：本文旨在将LLM驱动的程序发现扩展到真实评估稀缺且昂贵的科学领域。核心洞察是**利用LLM生成的代理评估器**，其结构不是预设的，而是从领域知识中生成，并随搜索协同进化。

### 2. 方法论：核心思想与关键技术细节

- **核心思想**：Janus采用**算法-评估器协同进化（Algorithm-Evaluator Co-Evolution）**范式。在进化目标程序（Target Programs）的同时，也进化代理评估器（Proxy Evaluators）。代理评估器的预测仅用于**筛选和排序候选**，以分配真实评估预算；候选者必须通过**真实验证**才能进入目标程序种群或更新最优解。

- **框架组件（基于AlphaEvolve的岛屿搜索框架）**：
    - **目标程序种群（$P^{alg}_i$）**：每个岛屿i维护的真实评估验证过的程序集合。
    - **评估器种群（$P^{eval}$）**：LLM生成的可执行代理评估器程序集合。
    - **真实结果档案（Archive, A）**：用于拟合和选择评估器的真实评估结果集合，有界、去重、平衡（保留高效用、最近、边界和多样性样本）。
    - **候选池（Candidate Pool, $C_i$）**：岛屿本地存放已被代理评估器评分但尚未进行真实评估的候选者。

- **算法流程（Algorithm 1）**：
    1. 在**提升事件（promotion event）**中，从候选池$C_i$中根据采集函数选择最优先候选者进行**真实评估**。
    2. 在**评估器进化事件**中，由LLM从评估器种群（父代+结构多样性启示）变异出新的评估器程序，在真实结果档案A上拟合、元评估（meta-evaluate）后，更新$P^{eval}$和活跃组合（Portfolio, $\Pi$）。
    3. 在**目标候选生成事件**中，LLM从$P^{alg}_i$变异出新的目标程序，由区域条件子组合$\Pi_{i(x)}$评分后，**临时*加入候选池$C_i$。
    4. **存档刷新（Archive Refresh）**：当有新的批量真实结果进入A时，重新拟合并选择评估器、更新$\Pi$，并重新评分过期候选。

- **关键技术一：评估器即程序（Evaluator-as-Program）**
    - 代理评估器被表示为可执行程序：$e = \langle g_\phi, \theta_\phi(A)\rangle$。其中 $g_\phi$ 是LLM生成的程序结构（可包含特征、方程、条件分支、低保真计算等），$\theta_\phi(A)$ 是基于真实结果档案A拟合的可调参数。
    - 这种表示允许LLM基于领域知识生成物理上合理的代理结构，通过少量真实标签校准参数，并将结构与参数分离以支持在线更新。

- **关键技术二：评估器选择与适配**
    - **晋升对齐的元评估目标（Promotion-aligned Meta-Objective）**：评估器好坏不取决于平均预测误差，而取决于其识别出高潜力候选的能力。公式为：
      $$F_{meta}(e) = \lambda_R(1 - Rk(e)) + \lambda_N Nk(e) + \lambda_\rho \rho(e)$$
      其中 $Rk(e)$ 是归一化风险（预测top-k是否包含近优程序），$Nk(e)$ 是NDCG（预测top-k与真实top-k的排序匹配度），$\rho(e)$ 是全局排序一致性。前两项权重更高。
    - **区域条件组合（Region-conditioned Portfolios）**：将当前目标程序按代码嵌入聚类，每个聚类视为一个区域。候选x根据其嵌入与区域质心的余弦距离分配到最近的区域，然后选择该区域信用（credit）最高的K个评估器组成子组合来评分。信用更新公式为：
      $$F_{e,r} = (1 - \alpha_{e,r})F_{meta}(e) + \alpha_{e,r} g_{e,r}$$
      其中 $\alpha_{e,r} = n_{e,r}/(n_{e,r} + \kappa)$ 根据历史证据量调整局部证据权重，$g_{e,r}$ 结合了该区域中有效且改进的推荐比例和归一化改进幅度。

- **关键技术三：真实锚定提升（Real-Anchored Promotion）**
    - **采集函数**：用于预算分配，平衡利用与探索：
      $$\alpha(x) = w_q \bar{p}_v(x)\bar{s}(x) + w_u \bar{p}_v(x)\bar{\sigma}(x) + w_n \eta(x)$$
      其中 $\bar{s}(x)$ 是预测质量，$\bar{p}_v(x)$ 是预测有效性概率，$\bar{\sigma}(x)$ 是组合不确定性，$\eta(x)$ 是嵌入区域的新颖性。有效性概率乘以质量和不确定性项，以避免在预测无效的候选上浪费预算。
    - **安全阀**：代理预测仅用于排序，*不直接决定最终结果*。所有晋升候选必须经过真实评估$f_{real}$，只有有效结果才能更新种群和最优解。此外，还定期将未排序的LLM后代直接送往真实评估，避免整个组合错判导致的搜索停滞。

- **实验设计严谨**：
    - 选择了来源真实、成本差距悬殊的多个典型案例，证明方法适用性。
    - 消融实验设计合理，明确验证了各组件的必要性和互补性。
    - 提供了详尽的附录，包含基准细节、基线协议、token成本分析、案例研究等，增强可复现性。
- **务实的安全保障**：严格坚持"代理评估仅用于预算分配，真实评估决定最终结果"的原则，有效避免了代理误差对最终优化结果污染的风险。

### 8. 不足与局限

- **算力与可复现性细节缺失**：未报告具体GPU资源、总仿真耗时等关键信息，使得成本估算和公平对比变得困难。
- **实验覆盖存在局限**：
    - 仅覆盖5个任务，且均属于**设计/控制类问题**，未涉及其他昂贵评估场景（如分子发现、蛋白质设计）。
    - 消融实验仅覆盖2个任务，无法充分泛化结论。
    - 随机种子数少，统计功效存疑。
- **对LLM能力的高度依赖**：性能与LLM骨干模型的领域知识和生成能力强相关（见骨干敏感性实验），在模型能力不足时，评估器进化的收益可能被抵消。此外，LLM的token消耗是Alg.-Only的数倍，在LLM服务成本高的环境中可能构成经济瓶颈。
- **潜在偏差风险**：
    - 评估器是在**当前历史档案**上进行选择，这可能导致对特定搜索区域或程序模式（如代码嵌入的聚类中心区域）的过度拟合。
    - 区域信用更新机制依赖少量晋升样本（$n_{e,r}$），过早的噪声反馈可能导致评估器信用被错误低估或高估，从而影响组合的构成。
- **应用限制**：Janus的适用前提是LLM能基于文本描述生成合理的代理结构。对于领域知识极其隐晦、难以显式表达的物理过程，该方法的性能上限可能受限。
