## 摘要
LLM应用既依赖于模型，也依赖于执行框架：这个程序决定每次调用能看到什么、进行多少次调用以及信任哪些答案。编码智能体现在可以通过搜索候选程序来发现强大的执行框架，但生成的产物是一块不透明的命令式代码，其逻辑步骤、运行时信号、物理执行决策和提示策略仍然隐含且特定于任务，迫使后续任务从头开始执行框架搜索。然而，其复用潜力是巨大的。搜索到的执行框架蕴含了重要知识，例如有效的逻辑步骤、关键信号、适应执行的物理操作决策以及有效的提示策略，但这些知识深埋在命令式代码中，没有可检查或可复用的结构，也不带有任何来源或元数据。Credo通过恢复搜索到的执行框架的结构化声明式描述，为每个提取的原语标注相关元数据，并将其全部编入带来源的目录，从而解决这一问题。随后，编译器可以绑定存储的原语，为新任务生成执行框架，而无需从头开始搜索。本文提供了初步结果，展示了我们方法的潜力，并提出了一个数据库社区非常适合处理的相关研究议程，包括基于成本的声明式目录编译以及模型和工作负载漂移下的目录维护。

## Abstract
An LLM application depends on both a model and a harness: the program that determines what each call sees, how many calls to make, and which answers to trust. Coding agents can now discover strong harnesses by searching over candidate programs, but the resulting artifact is an opaque block of imperative code whose logical steps, runtime signals, physical execution decisions, and prompt strategies remain implicit and task-specific, forcing subsequent tasks to start the harness search process from scratch. The potential for reuse, however, is substantial. A searched harness encodes significant knowledge, such as the logical steps that work, the signals that matter, the physical operator decisions that adapt execution, and the prompt strategies that are effective, yet this knowledge is buried in imperative code with no inspectable or reusable structure, nor does it carry any provenance or metadata. Credo addresses this problem by recovering a structured declarative description of a searched harness, tagging each extracted primitive with relevant metadata, and cataloguing all of it with provenance. A compiler can then bind stored primitives to generate harnesses for new tasks without having to start the search over from scratch. This paper provides preliminary results demonstrating the potential of our approach and lays out a related research agenda that the database community is well-positioned to tackle, including cost-based compilation over declarative catalogs and catalog maintenance under model and workload drift.

## 1. 论文的核心问题与整体含义

**研究动机与背景：**

- LLM应用的行为高度依赖其"执行框架"（harness）——即决定每次模型调用的输入信息、调用次数以及哪些答案被采纳的程序逻辑。
- 编码智能体可通过**执行框架搜索**（harness search）自动发现高性能的harness，基于准确率和成本对候选程序进行演化式迭代（如Meta-Harness）。
- 然而，搜索出的harness是一块**不透明的命令式代码**，其中蕴含的知识——包括有效的逻辑步骤、关键运行时信号、物理执行决策、提示策略——全部混为一体，且缺乏结构、元数据和可检查性。
- 这意味着：对于每一个新任务，都必须**从头开始重新搜索**，造成巨大浪费。数据库领域曾面对类似问题：UDF（用户自定义函数）作为黑盒无法被优化，但通过UDF内省和从过程式代码中恢复声明式表达式，打开了优化空间。论文主张将这一思路引入LLM harness管理。

**核心含义：** 搜索得到的harness蕴含可泛化的知识，应将其从"一次性命令式代码"转化为**持久、可检查、可重用的声明式原语目录**，使新任务可通过廉价编译而非昂贵搜索获得harness。

## 2. 论文提出的方法论

**核心思想：** Credo从搜索得到的harness中恢复出结构化声明式描述，将内部逻辑分解为四类可复用原语，附上元数据和溯源信息后编入目录，最终由编译器为新任务合成harness。

**四类原语：**

- **骨架（Skeleton）**：命名算子步骤及其依赖关系构成的有向无环图（DAG），即逻辑计划，描述harness计算什么、按什么顺序计算——类似于数据库查询计划。
- **信念（Belief）**：在计划点计算出的派生属性，类型限于 {bool, enum, int, float, str}，供策略读取以做物理算子决策。分为三类：输入推导属性（如 is_semantic_query: bool）、中间结果属性（如 extraction_confidence: float）、输出质量属性（如 schema_match: bool）。
- **策略（Policies）**：类似数据库系统中的物理算子选择规则，对信念值进行条件判断，选择逻辑步骤的物理实现（如模型、参数、执行策略），将"步骤做什么"与"如何运行"解耦。
- **提示模板（Prompt templates）**：搜索发现的参数化自然语言规范，含可绑定槽位（如 persona = {p}），承载推理策略、指令模式、输出格式或角色设定。

**两个阶段：**

1. **离线目录构建**：抽象器（abstractor）提取原语 → 层次标记器（level-tagger）判断迁移范围（L1功能型可跨域复用、L2源特定型保留本地）→ 图书管理员（librarian）存入两级目录（general/共享层 + specific/溯源层），含完整的溯源信息。
2. **在线编译**：编译器为目标输入选择原语组合、绑定槽位值（如 k := 8, persona := attorney）、组装声明式计划并降级为可运行的 harness.py；若无组合达到阈值则回退到搜索。

**关键设计细节：** 原语的迁移范围基于模式（pattern）而非表面文本或常数判断；源特定常数先被提升为可绑定槽位，但参数化本身不保证可迁移性，只有经提升后仍存活的模式才标记为L1。

## 3. 实验设计

**数据集与场景：** 覆盖两个功能域——检索（finance、legal）与推理（math、polyreason），共四个数据集：

每个数据集采用三路分割：search（100问，供搜索代理迭代）、in-distribution（100问，同源留出，用于从Pareto前沿选最优harness）、cross-distribution（300问，对齐但结构不同，用于评估泛化）。检索任务中去除金证据标注，将证据定位纳入任务范畴。

**对比方法：**

- **Round-trip测试**：原harness vs. 恢复→编译后的harness，在相同100问in-distribution分割上对比准确率和成本。
- **Primitive Reuse测试**：四个源→目标转移（检索：legal→finance, finance→legal；推理：math→polyreason, polyreason→math），对比三种编译器配置——brief-only（无目录原语）、single-domain（单一源域L1原语）、open-library（除目标域外全部目录）。

**评估指标：** 任务准确率（gpt-5-mini评判）与harness成本（每问推理成本¢/q），二者合并比较而非合成单一分数。

## 6. 论文的主要结论与发现

- **目录构建可行**：所有骨架步骤均为功能型（L1），四个域源特定步骤数为0；检索程序约为推理程序的两倍大小（≈26 vs. 14），源特定细节仅集中在决策逻辑部分。
- **Round-trip保真度高**：准确率差最大为±0.011（finance +0.011, legal −0.007, math −0.010, polyreason +0.007），每问成本差在±0.013¢/q以内；恢复+编译一次成本约$2.3-2.8，远低于搜索的$43-72。
- **原语可跨域复用**：检索域转移效果显著——legal→finance从15.7提升至28.3（搜索harness为27.7），finance→legal从43.4提升至66.3（恢复搜索结果的76%）；open-library配置与single-domain结果相近（28.2 vs. 28.3；64.6 vs. 66.3）。
- **推理域转移依赖操作点**：math→polyreason降低了成本（$0.03–0.04/问，比brief-only低5–7倍）但准确率低于基线；polyreason→math通过ensemble和answers_agree信念提升准确率（39.6→44.6/45.4）。
- **搜索harness有过度拟合倾向**：搜索得到的polyreason harness从分布内72%跌至跨分布47%，math从67%跌至37%；Credo编译的harness不出现相同精度下跌，在polyreason→math上甚至超出搜索程序约8个百分点。

## 7. 优点

- **新颖的定位**：将数据库领域的UDF内省/声明式恢复思想系统性地迁移到LLM harness管理，填补了搜索与部署之间的知识复用空白。
- **清晰的抽象设计**：骨架、信念、策略、提示模板四类原语构成完整且可操作的分层体系，逻辑/物理分离思想与数据库查询规划一脉相承。
- **溯源与管理并重**：general/共享层与specific/溯源层的双级目录设计，既支持复用又保留完整性，每个原语都有清晰的来源追踪。
- **严格的验证方法论**：round-trip测试同时匹配准确率和成本是巧妙的保真度检验设计，有效排除"编译器靠模型先验解题"的混淆。
- **成本效益显著**：将每任务搜索成本从数十美元/数小时降至数美元/数十分钟，是实现加速的实际收益。
- **开放了清晰的研究议程**：基于成本的编译、目录维护、执行上下文恢复、可插拔后端——为数据库社区提供了明确的研究方向。

## 8. 不足与局限

**实验层面：**

- 论文自述为初步结果，实验规模有限（3种子×3复制），未报告统计显著性检验。
- 跨分布评估中Math和Polyreason的搜索harness准确率大幅下降，提示搜索可能过度拟合分布内数据，这既说明了Credo的优势，也暗示搜索流程本身可能不够稳健。
- 每个域只有3个搜索轨迹，对搜索方法的种间变异性刻画不足。

**方法层面：**

- 编译器仍是**规则式重写器**而非成本优化器，靠角色匹配和自然语言元数据选择原语，缺乏代价模型和全局优化。
- 推理域转移效果强烈依赖源策略编码的操作点，编译器无法自行调整以适应当前成本-准确率偏好；缺乏类似数据库优化器的成本枚举机制。
- 抽象器仅恢复harness程序本身，未覆盖系统提示、技能定义、工具配置等执行上下文——作者承认finance→legal的残余准确率差距可能源于此。
- 缺少对L1/L2标记质量的系统评估，未验证标记器判断与"真正可迁移性"之间的一致性。

**应用限制：**

- 原语的行为随模型和提示变化而变化，缺少正式语义等价保证；Credo目前仅提供行为层面的保真度验证，而非UDF设置中可用的语义等价性证明。
- 对搜索harness的质量有依赖——若搜索产出的harness本身不佳或过拟合，恢复的原语质量也会受限。
