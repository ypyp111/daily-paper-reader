## 摘要
基于LLM的程序进化系统（如FunSearch和AlphaEvolve）已展现出发现新算法的强大能力，但通常孤立地优化每个任务，在完成后丢弃搜索经验。我们提出ε-MemEvo，一个用于LLM程序进化中跨任务知识迁移的框架。ε-MemEvo将先前经验存储为与任务无关的策略记忆：成功算法策略的紧凑自然语言摘要，而非原始代码，从而支持跨不同API和评估器的任务迁移。为避免语义不匹配记忆带来的负迁移，ε-MemEvo使用自适应注入门控，决定是否注入检索到的记忆以及注入强度。我们在涵盖数学优化和系统工程领域的8个多样化优化基准上评估ε-MemEvo，采用排除目标任务记忆条目的内容级留一法协议。在主要GPT-5骨干上，ε-MemEvo在所有8个任务上相比AdaEvolve提升了AUCC，平均相对增益为+8.7%，平均早期收敛速度提升+9.4%。消融实验表明，朴素记忆注入可能灾难性失败，而自适应门控在所有五个消融任务中保持安全。数据更新的后验在观测状态上是可解释的：在改进搜索期间倾向于跳过，在早期和晚期平台期从跳过转向提示。这些增益的计算开销不到1%。

## Abstract
LLM-based program evolution systems such as FunSearch and AlphaEvolve have shown strong ability to discover novel algorithms, but typically optimize each task in isolation, discarding search experience after completion. We introduce $\varepsilon$-MemEvo, a framework for cross-task knowledge transfer in LLM program evolution. $\varepsilon$-MemEvo stores prior experience as task-agnostic tactic memories: compact natural-language summaries of successful algorithmic strategies rather than raw code, enabling transfer across tasks with different APIs and evaluators. To avoid negative transfer from semantically mismatched memories, $\varepsilon$-MemEvo uses an adaptive injection gate that decides whether retrieved memories should be injected, and at what intensity. We evaluate $\varepsilon$-MemEvo on 8 diverse optimization benchmarks spanning mathematical optimization and systems engineering, using a content-level Leave-One-Out protocol that excludes target-task memory entries. On the primary GPT-5 backbone, $\varepsilon$-MemEvo improves AUCC over AdaEvolve on all 8 tasks, with a mean relative gain of +8.7%, and improves early-stage convergence by +9.4% on average. Ablations show that naive memory injection can fail catastrophically, while adaptive gating remains safe across all five ablation tasks. The data-updated posterior is interpretable in observed states: it favors skip during improving search and shifts from skip to hint across early and late plateaus. These gains incur less than 1% computational overhead.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：现有LLM程序进化系统（如FunSearch、AlphaEvolve）通常逐任务孤立优化，在完成一个优化任务后，会完全丢弃搜索经验，导致**每个任务都从零开始（"amnesic"行为）**。这使得相关任务之间出现大量冗余探索、冷启动收敛缓慢，并浪费API预算。
- **具体场景**：例如，系统在优化完一个几何装箱问题后，学到了"对称偏移的结构化网格布局能最小化重叠"这一可复用策略，但现有系统无法将其应用到相关的装箱任务中。相比之下，人类研究者自然会基于已有经验进行迁移。
- **论文提出的思路**：引入ε-MemEvo框架，将跨任务知识迁移形式化为**自适应干预问题**——不仅要解决"如何提取和检索"记忆，更要解决"何时注入、注入多强"的控制问题。
- **关键洞察**：跨任务迁移在进化编码中**首先是安全问题，而非单纯的检索问题**。盲目注入不匹配的记忆可能导致灾难性负迁移，因此需要一个自适应门控机制来保证安全性。

### 2. 论文提出的方法论：核心思想、关键技术细节

#### 2.1 整体框架
ε-MemEvo以AdaEvolve为基座，新增两个跨任务模块：
- **Tactic Memory Bank（策略记忆库）**：负责内容级迁移（存什么、怎么取）；
- **Adaptive Injection Gate（自适应注入门）**：负责控制级迁移（何时注入、以何种强度注入）。

#### 2.2 Tactic Memory Bank（内容级迁移）
- **策略提取**：任务成功完成后，使用GPT-4.1-mini从最终最优程序中提炼出**任务无关的自然语言策略摘要**（而非原始代码），例如"两阶段优化：贪心初始化+梯度下降"。
- **存储内容**：每条记忆包含策略文本、方法类型标签、任务描述和嵌入向量，仅在后续任务中可用。
- **语义检索**：对新任务描述用text-embedding-3-small（1536维）嵌入，通过**分数加权相似度**检索top-3策略：
  - 相似度公式：`rk = cos(ej, ek) · (1 + 0.3 · log(1 + max(Δk, 0.01)))`，其中Δk为该策略相对基线的分数提升。

#### 2.3 Adaptive Injection Gate（自适应注入门）
- **状态空间**：6个离散状态，由两个特征组合：
  - 搜索阶段：improving（改进率ρ>0.1）、plateau（0.02<ρ≤0.1）、stagnating（ρ≤0.02）；
  - 任务阶段：early（t/M<0.4）、late。
- **动作空间**（3种注入强度）：
  - `skip`：不注入，使用基础提示词；
  - `hint`：将检索到的策略作为可选参考；
  - `guide`：将最优策略作为推荐方法，并注入范式突破生成过程。
- **Thompson Sampling决策**：每个(s,a)对维护Beta(α,β)分布，每轮采样后选择最大θ对应动作。
- **先验设置**：`Prior(improving, skip)=Beta(3,1)`、`Prior(stagnating, guide)=Beta(3,1)`（体现"改进期偏好跳过、停滞期偏好引导"的先验直觉），其余为Beta(1,1)。
- **延迟奖励**：窗口w=5，奖励为`Rt = 1[f*t+w > f*pre + ε]`，成功则α+1，失败则β+1；用FIFO队列解决并发等待问题，任务边界处清算未决记录。
- **核心目的**：门控主要作为**防负迁移的闸门**（而非单纯奖励最大化控制器）——当检索策略不匹配时，guide后验在几次失败后迅速坍缩，策略自然回退到skip。

#### 2.4 Leave-One-Out评估协议
- 评估任务Tk时，记忆库B−k排除Tk自身产生的所有条目，确保迁移完全来自**其他任务**；但策略π保留完整后验（学到的是任务无关的状态-动作映射）。

### 8. 不足与局限

#### 8.1 实验覆盖不足
- 仅评估2个LLM骨干（GPT-5、Gemini-3-Pro），未验证在**较弱或开源的LLM**上的泛化性；
- 未测试记忆库扩展到**数百条目**时的检索精度、门控校准和负迁移频率变化——当前仅8个任务对应8条记忆，规模有限；
- 消融任务数量（5个）偏少，且灾难性失败集中在同一语义簇（EPLB↔LLM-SQL）。

#### 8.2 消融覆盖盲区

#### 8.3 方法与框架的局限
- ε-MemEvo**增强而非替代**基座进化框架，无法弥补底层搜索的勘探失败；
- 记忆银行仅在任务级别积累（每任务一条），没有层次化、细粒度的记忆结构；
- 检索使用简单的加权余弦相似度，未探索更精细的语义匹配或学习式检索器。

#### 8.4 偏差风险
- **种子范围有限**：5个种子（{42,0,1,2,3}）可能未充分覆盖随机性分布；
- **T90%指标存在失真**：当AdaEvolve最终分数显著更低时，其T90%=1是因为"达到自身90%的更低目标"在迭代1即完成，该指标对照需谨慎解读（论文对此做了脚注说明）；
- 论文未提供跨基座框架（如直接增强FunSearch或AlphaEvolve而非AdaEvolve）的验证。

- 论文承认每任务2–34 GPU小时的高算力需求，虽总墙钟时间为AdaEvolve的0.69倍，但绝对能耗仍不容忽视，规模化可能带来更大的环境成本。
