## 摘要
大型科学代码库的升级与重写历来是一项重大挑战。尽管使用大型语言模型（LLM）的进化搜索可以移植并加速遗留代码，但仅靠提示中的修复反馈无法阻止后续候选方案重复相同的错误。我们提出证书驱动进化搜索（Certificate-Driven Evolutionary Search, CDES），它通过从失败候选中提取的可强制执行限制来扩展进化搜索，这些限制被记录为假设证书、检查器证据和经论证的限制。其控制逻辑通过拒绝、回溯和定向修复来强制执行这些限制，同时保留兼容的编辑。我们将 CDES 应用于 Geant4 工具包中两个粒子模拟函数的 CPU 到 GPU 转换，并使用一个超越单元测试的测试框架进行评估，该框架结合了形式化检查、数值比较、物理检查和 GPU 安全性测试。生成的实现相比 CPU 代码实现了 13.78 倍和 23.54 倍的函数级加速，包括数据转换和传输；对于其中一个函数，GPU 吞吐量比专家实现高出 14.9%，当组合互补组件时达到 16.1%。在一项针对执行设置的消融实验中，证书反馈使通过所需正确性检查的候选比例从 55% 提高到 90%。

## Abstract
The upgrade and rewriting of large scientific codebases has traditionally been a major challenge. While evolutionary search with large language models (LLMs) can port and accelerate legacy code, repair feedback in prompts alone does not prevent subsequent candidates from repeating the same errors. We introduce Certificate-Driven Evolutionary Search (CDES), which extends evolutionary search with enforceable restrictions derived from failed candidates, recorded as certificates of assumptions, checker evidence, and justified restrictions. Its control logic enforces these restrictions through rejection, backtracking, and targeted repair while preserving compatible edits. We apply CDES to CPU-to-GPU translation of two particle-simulation functions from the Geant4 toolkit, evaluated with a harness that goes beyond unit tests to combine formal checks, numerical comparisons, physics checks, and GPU safety tests. Generated implementations achieve 13.78x and 23.54x function-level speedups over CPU code, including data conversion and transfers; for one function, GPU throughput exceeds an expert implementation by 14.9%, reaching 16.1% when complementary components are combined. In an ablation over execution settings, certificate feedback increases the fraction of candidates passing required correctness checks from 55% to 90%.

- **核心问题**：如何把失败候选所暴露的信息，转化为对后续搜索**可强制执行**的限制，从而提升自动移植的可靠性与可扩展性？

## 2. 方法论：CDES

### 2.1 核心思想

- 在 AlphaEvolve 风格的进化搜索核心（用 ShinkaEvolve 实现）之上，增加一个**证书数据库**（certificate database）与配套控制逻辑。
- 将失败候选记录为**证书**：包含冲突的选择、被违反的需求、支撑性假设与检查器证据，以及据此论证出的**可强制执行限制**。
- 关键区别：CDES **不依赖提示合规性**，而是由控制逻辑独立强制已验证的限制——即使 LLM 再次提出冲突方案，也会被拒绝。

### 2.2 关键组件与流程

- **基础搜索循环**：种子程序初始化程序数据库 → 父选择 → 变异 LLM 提出代码或执行设置 → 评估 harness 返回程序与分数（进入程序数据库）、失败（进入证书数据库）。
- **检测与认证（Detection and Certification）**：
  - 评估 harness 检测需求违规；
  - 冲突检查与分析器结合已存证书和对代码组件依赖的符号检查，审查未完成候选；
  - 拟议限制在使用前需先被验证，才能用于阻断后续候选中的同一冲突。
- **撤销与定向修复（Undo and Targeted Repair）**：
  - CDES 控制逻辑拒绝冲突组合、补充必需组件、在**保留兼容编辑**的前提下修复选择；
  - 支持三种动作：拒绝（rejection）、回溯（backtracking）、重启（restart）、定向修复；
  - 类比 CDCL SAT 求解器从冲突中学习限制并回跳（backjump），但 CDES 不声称"无解"。
- **自改进机制**：累积的证书改变未来哪些修改被允许，而**无需重新训练 LLM**；只需通过 API 调用前沿模型，不需要模型权重。
- **思想来源**：RLSF 的符号反馈、CDRL 的约束强化学习、Neo 的程序构造冲突学习；以及程序分析/合成中利用程序摘要、简化模型、保持行为的重写条件、执行状态对齐、未完成程序检查、循环不变量推断等方向（用于指导工具请求和可复用限制的构造）。

### 2.3 两项主要贡献

1. **证书驱动进化搜索机制**：把冲突转化为经证实的限制，并通过定向拒绝与修复强制执行，同时保留兼容改动。
2. **科学优化与评估 harness**：将该机制与工具选择、正确性检查集成，实现 CPU 程序到 CUDA（NVIDIA GPU 编程平台）的翻译。
