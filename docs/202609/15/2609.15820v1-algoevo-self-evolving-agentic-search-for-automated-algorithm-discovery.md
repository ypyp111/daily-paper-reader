## 摘要
大语言模型通过合成可执行代码推动了自动化算法发现，但现有框架将它们困在具有预定义控制流的刚性搜索流程中。这一局限限制了自适应推理，阻碍了跨范式迁移，并丢弃了有价值的执行反馈。我们提出 AlgoEvo，一个统一的智能体框架，将自动化算法发现转化为交互式、知识累积的过程。自主智能体基于运行时反馈动态检查、诊断和编辑代码。设计技能中心将特定范式知识与核心发现引擎解耦，使单一工作流能够无缝处理单目标、多目标和多组件设计。同时，分层经验机制将搜索轨迹组织为任务级树以指导探索，并将跨任务模式整合为可复用技能。在六个代表性基准任务上，AlgoEvo 以显著更少的评估次数和更低的 token 消耗匹配或超越专用方法，展现出强大的任务内累积、跨任务迁移，以及通过灵活激活技能复现或超越现有最先进性能的能力。

## Abstract
Large language models have advanced automated algorithm discovery by synthesizing executable code, but existing frameworks trap them in rigid search pipelines with pre-defined control flows. This limitation restricts adaptive reasoning, blocks cross-paradigm transfer, and discards valuable execution feedback. We propose AlgoEvo, a unified agentic framework that transforms automated algorithm discovery into an interactive, knowledge-accumulating process. An autonomous agent dynamically inspects, diagnoses, and edits code based on runtime feedback. A design skill hub decouples paradigm-specific knowledge from the core discovery engine, allowing a single workflow to seamlessly handle single-objective, multi-objective, and multi-component design. Meanwhile, a hierarchical experience mechanism organizes search trajectories into a task-level tree to guide exploration and consolidates cross-task patterns into reusable skills. Across six representative benchmark tasks, AlgoEvo matches or surpasses specialized methods with substantially fewer evaluations and reduced token consumption, demonstrating strong intra-task accumulation, cross-task transfer, and the ability to reproduce or exceed existing state-of-the-art performance through flexible skill activation.

## 1. 核心问题与研究动机

- **背景**：自动化算法发现（AAD）/ 基于大语言模型的自动化启发式设计（LLM-AHD）已能直接合成可执行启发式代码，并在单目标、多目标（如 MEoH）、多组件（如 E2OC、MOTIF）等范式上取得进展。
- **核心痛点**：现有框架把 LLM 嵌入**专家预定义的刚性演化流水线**中，LLM 只是被动代码采样器，导致三类问题：
  - 无法进行交互式调试、诊断分析与深层结构重构；
  - 范式强耦合造成**框架碎片化**，不同设计任务需维护独立代码库；
  - 仅用标量性能反馈，丢失"为什么成功/失败"的结构化执行细节，搜索沦为孤立的试错，难以累积与迁移算法经验。
- **整体含义**：论文主张把算法发现从"固定流程 + 被动生成"升级为**交互式、知识累积、自演化的科学过程**：单一智能体引擎跨范式工作，并把历史轨迹转化为可复用的设计与经验知识。

## 2. 方法论

### 2.1 问题形式化（第 2 节）

- 领域 $D$ 由实例空间、解空间、目标函数 $f_d$ 定义；solver 由可设计策略 $\Pi=(\pi_1,\dots,\pi_K)$ 组成，$K=1$ 为单启发式、$K>1$ 为多组件联合设计，算法空间 $S=S_1\times\cdots\times S_K$。
- 算法性能 $F_d(x|\Pi)=\phi_d(f_d(x,s(x|\Pi)))$（多目标时 $\phi_d$ 为超体积等标量指标），发现目标为在预算 $B$ 下最小化 $\mathbb{E}_{x\sim X_d}[F_d(x|\Pi)]$。

### 2.2 智能体搜索循环（Agentic Search Loop）

- 每个时刻的发现状态 $s_t=(\Pi_t, C_t, E_t, F_d(x|\Pi_t))$，其中 $C_t$ 为工作上下文（代码、近期改动、诊断观察、推理），$E_t$ 为经验库。
- 智能体自主选择动作 $a_t$：**Inspect（读代码）/ Retrieve（检索经验）/ Diagnose（归因诊断）/ Analyse interaction（组件耦合分析）/ Edit（改代码）/ Evaluate（评估）/ Commit（提交）/ Terminate**，自行决定"做什么"和"何时做"，不遵循固定周期。
- 即时奖励定义为性能改进 $r_t=F_d(x|\Pi_{t-1})-F_d(x|\Pi_t)$；最大化累计改进 $\sum_t r_t$ 通过望远镜求和等价于最小化最终性能 $F_d(x|\Pi_T)$，从而与全局目标一致。

### 2.3 设计技能中心（Design Skill Hub）

- 把**范式相关知识外化为可插拔技能**，而非写进搜索引擎：每个技能声明 (i) 各可设计策略的角色、(ii) 代码接口、(iii) 合法修改原则、(iv) 任务评估约定。
- 生命周期：任务开始时按条件匹配并**激活**技能（t=0）；任务结束时把证据固化进经验库，技能**仅在跨任务**时演化（t=T）——当同一设计模式在**至少两个不同任务**上被验证有效时，抽象回技能中心。
- 技能也可编码已有算法设计方法（EoH、ReEvo、FunSearch、MEoH、NSGA-II、MOEA/D）的方法论知识，继承其归纳偏置但保留自主执行过程。

### 2.4 分层经验库（Hierarchical Experience Bank）

- **Level 1 经验卡片**：仅在评估事件（产生奖励）时更新，记录设计上下文、修改、奖励与理由，跨评估、跨任务持久保存。
- **Level 2 任务级经验树**：节点为卡片，边为"派生自"关系，用 MCTS 四阶段维护：
  - *Selection*：按情境 $q$ 下的 UCB 选择节点 $\text{UCB}(v|q)=\bar r(v|q)+c\sqrt{2\ln N/n(v,q)}$；未访问节点用全局均值加探索激励；
  - *Expansion*：验证过的候选作为子节点挂接；
  - *Evaluation*：评估得到奖励 $r_t$；
  - *Backpropagation*：向祖先传播，维护子树评估数 $m(v)$ 与累计奖励 $S(v)$，子树价值 $\bar R(v)=S(v)/m(v)$ 衡量该设计方向的历史平均收益。
- **情境检测**：从遥测中识别四类搜索情境——*stagnation*（最近 4 次提交无改进，权重 0.30）、*sparse front*（Pareto 存档覆盖有缺口，0.25）、*bottleneck*（单一组件占归因质量 >0.5，0.20）、*coupling*（交互度量 >0.05，0.20），可同时成立，并据此加权检索历史经验。
- **Level 3 跨任务整合**：跨任务反复验证的设计模式被抽象进技能中心，实现"经验 → 知识 → 状态感知搜索"的闭环（Algorithm 1）。

## 6. 主要结论与发现

- **性能**：仅切换激活的设计技能，单一引擎即在六任务上匹配或超越专用方法。单启发式上 TSP 训练 5.986 / 测试 7.007（优于最强基线 4–7%，较 NN 提升 12.3%），CVRP 训练 12.698 / 测试 24.150。
- **样本效率**：单启发式与多目标任务在约 33–39 次评估内即达最终质量（预算的 1/13 左右），而基线跑满 500 次仍未追上；多组件任务则需动用大部分预算（271–275 次），反映解空间更大、耦合更强。
- **多目标**：Bi-TSP 上 HV 0.827、IGD 0.036 均为最优；Bi-FJSP HV 0.911 最优，但 IGD 0.162 略逊于 MEoH 的 0.143（前沿逼近性稍弱），作者归因于本文前沿能触及低目标值角落而 MOEA/D 前沿近乎塌缩为一点。
- **多组件**：CVRP-DR 两个划分均最优（8.860 / 8.999），FJSP 4-Ops 在留出集上最优（1927.5）且优于专家算子，增益在留出集上更明显（说明是迁移而非过拟合）。
- **经验累积有效**：多轮累积单调改进（TSP 4.8928→4.7995，Bi-FJSP HV 0.1549→0.1862，预算固定）；暖启动优于冷启动且方差更小，说明传递可执行代码比注入抽象策略描述更有效。
- **跨任务迁移有效但有限**：CVRP→CVRP-DR 成本由 10.314 降至 9.816（−4.8%），TSP→Bi-TSP HV 提升 4.7%。
- **行为差异**：不同 seed 呈现编辑主导 / 诊断主导 / 混合三种搜索风格，诊断主导的 seed 取得最佳成本（8.281），与"先归因再修改"的设计原则一致。
- **方法技能可解耦复用**：把 EoH/ReEvo/FunSearch/MEoH/NSGA-II/MOEA/D 的方法论编码为技能交给 AlgoEvo，质量不降反升，且评估次数大幅减少（如 TSP 仅 19–22 次）。

## 7. 优点

- **架构层面解耦彻底**：搜索循环、范式知识（技能中心）、经验记忆三层分离，新增范式只需加技能而无需改引擎，直接回应了框架碎片化问题。
- **把"设计过程"本身作为搜索对象**：动作空间（读/诊断/耦合分析/编辑/评估/提交）与情境感知检索使搜索轨迹可自适应，而非固定 generate-evaluate 周期；奖励设计（累计改进 = 最终性能）在理论上自洽。
- **经验机制层次清晰且可验证**：经验卡片 → MCTS 式任务树（UCB + 子树价值 + 反传）→ 跨任务技能抽象，且要求"至少在两个任务上验证"才提升为技能，降低了噪声经验污染风险。
- **诊断驱动的归因分析**：把组件归因与耦合度量引入搜索，使多组件任务从"孤立调参"转向"协同设计"，并用具体轨迹（表 11）佐证。
- **实验设计有说服力**：统一平台与预算、含留出集泛化、消融 + 迁移 + 冷/暖启动 + 方法技能迁移 + 行为分析多角度验证；token 与评估次数上明显更省（多组件任务 token 约为最强基线的 1/4–1/6）。
- **诚实报告失败面**：明确说明 Bi-FJSP IGD 落后、暖启动与主实验基线不同、行为-性能相关性需更大样本等。

## 8. 不足与局限

- **算力信息缺失**：未报告 GPU 型号/数量/时长，仅有评估次数与 token，难以评估总计算成本与可复现的硬件门槛（虽然声明提供源码）。
- **统计强度有限**：仅 3 个随机种子，部分结果方差极大；未做显著性检验；多目标任务只报告训练实例质量，缺少多目标在留出集上的泛化证据。
- **部分实验不可直接横向比较**：消融、暖启动使用独立批次或不同任务规模（如 100 城市 vs 50 城市），作者自己也提示绝对值不宜跨表比较，削弱了结论的量化强度。
- **性能并非全面最优**：Bi-FJSP 的 IGD 落后 MEoH；多组件任务需消耗大部分评估预算，早停优势不复存在。
- **跨任务迁移的适用边界受限**：作者承认迁移主要在同一问题族内有效，缺乏系统性的知识适用性判据，存在负迁移风险。
- **token 开销随经验累积膨胀**：复杂多组件设置下上下文变长导致 token 开销上升（如 139M/118M），缺少记忆压缩与上下文管理方案，规模化到更长搜索horizon存在瓶颈。
- **长时程可靠性**：智能体依赖序贯、相互依赖的决策，作者指出情境 UCB 与经验反馈虽能稳定探索，但降低轨迹方差、保证长程可靠性仍需进一步研究。
- **设计范围受限**：评估中固定了外围 solver、可行性检查与评估接口，只优化预定义的少量可演化单元（1–4 个），未验证对整个求解流水线的结构化协同设计；对通用编码智能体（SWE-agent 等）的对比也仅在相关工作层面讨论，未做实验比较。
- **情境阈值与权重为手工设定**（τs=4、τc=0.05、τb=0.5 及各检索权重），论文未给出敏感性分析，可能引入任务相关的偏置。
