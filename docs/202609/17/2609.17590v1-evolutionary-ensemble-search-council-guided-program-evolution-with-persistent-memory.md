## 摘要
演化集成搜索（EES）通过专家引导的程序演化来构建机器学习流程。一个角色专业化的委员会将任务证据和实验结果转化为结构化的搜索方向。一个编排器将这些方向分配给执行专家和一个演化引擎。该引擎选择已评估的父代，诊断其错误，并通过代码变异、结构化流水线编辑和交叉产生后代。每个子代都必须执行并获取自身的验证证据。种群档案保留有用的备选方案，而兼容的预测在验证门控的集成阶段进行竞争。搜索通过相对父代的算子信用、会话记忆以及跨运行检索的按问题索引经验进行自适应。我们详细说明这些机制，区分它们的执行特征，并定义在候选方案的计算发生变化时比较候选方案所需的契约。一个公开的 MLE-bench Lite 开发账本记录了 22 项任务中 19 项（86.36%）达到奖牌阈值的产物，最佳结果为 11 枚金牌、5 枚银牌和 3 枚铜牌。这些流程涵盖文本、图像、表格、音频、科学几何和确定性变换。该活动包括运行间的评分反馈、外部来源路径和混合确认程序；其汇总结果是一项已实现的开发成果，而非盲目的自主智能体成功率。该报告为累积式可执行搜索贡献了一种具体架构，并对其跨模态开发成果进行了版本化记述。

## Abstract
Evolutionary Ensemble Search (EES) constructs machine-learning procedures through expert-guided program evolution. A role-specialized council turns task evidence and experimental results into structured search directions. An orchestrator allocates these directions to execution specialists and an evolutionary engine. The engine selects measured parents, diagnoses their errors, and produces descendants through code mutation, structured pipeline edits, and crossover. Each child must execute and acquire its own validation evidence. Population archives retain useful alternatives, while compatible predictions compete in a validation-gated ensemble stage. Search adapts through parent-relative operator credit, session memory, and problem-indexed lessons retrieved across runs. We specify these mechanisms, distinguish their execution profiles, and define the contracts required to compare candidates as their computations change. A public MLE-bench Lite development ledger records medal-threshold artifacts on 19 of 22 tasks (86.36\%), with best outcomes of 11 gold, five silver, and three bronze. The procedures span text, images, tables, audio, scientific geometry, and deterministic transformations. The campaign includes grade feedback between runs, external-source routes, and mixed confirmation procedures; its aggregate is an achieved development result, not a blind autonomous-agent success rate. The report contributes a concrete architecture for cumulative executable search and a versioned account of its cross-modal development outcomes.

## 1. 核心问题与整体含义（研究动机与背景）

- **问题定位**：机器学习工程的核心困难不是"选超参数"，而是**选择计算本身**——用哪些数据、如何表示、拟合什么过程、如何构造最终预测。这类选择是**可执行程序层面的搜索**。
- **现有方法谱系**：
  - **MLE-bench** 提供 Kaggle 衍生任务的本地评分与历史奖牌阈值，作为评测基准。
  - **MLE-STAR** 检索候选方案 → 消融定位关键代码块 → 定向精炼 → 集成。
  - **MARS** 结合成本约束的蒙特卡洛树搜索、模块化实现与对比式反思记忆。
  - **遗传编程 / FunSearch / AlphaEvolve** 用演化或 LLM 提案搜索可执行程序。
  - **AutoML 与集成选择（Caruana 等）** 处理流水线搜索与异构预测器组合。
  - **Reflexion** 用文本反馈记忆影响后续尝试，但不更新模型权重。
- **EES 的差异化动机**：有效搜索必须同时做到三件事——**保留备选方案**、**把观测到的误差连接到后续编辑**、**在当前实验结束后仍保留有用经验**。已有工作少有把"结构化专家评审 + 持久演化种群 + 相对父代的算子信用 + 跨运行检索"整合为一个组织机制。
- **核心主张**：把"**提议一个改动**"与"**测量该改动结果**"严格分离——LLM 推理只引导搜索方向，不决定结果；子代在通过对比协议执行前**没有适应度**。

## 2. 方法论：核心思想、关键技术细节与流程

### 2.1 形式化对象与契约

- **任务**：`T = (D_tr, D_te, m, C, B)`，分别表示训练样本、测试输入、度量、输出契约、资源上限。额外数据源须有显式访问状态；**来源可用性 ≠ 预测有用性**。
- **可执行候选**：`x = (u_x, z_x)`，其中 `u_x = (d_x, f_x, h_x, a_x, p_x, q_x)` 分别刻画数据访问与划分、表示/特征程序、模型或算法结构、拟合过程、推理、后处理/集成拓扑；`z_x` 记录祖先、执行状态、诊断、测量与产物标识。
- **对比协议 κ**：定义评测行、目标语义、度量计算与拟合期可用信息。**改变验证划分本身不构成有效改进**——两者必须在共享 κ 下重评后才能排序。
- **执行接口**：`Eval_κ(u_x; D, B_x) → (Ŷ_val, Ŷ_te, Q_κ(x), z_x)`；超时/异常/非法产物是**类型化失败**，而非任意低适应度。
- **在位者**：`x*_g ∈ argmax_{x∈E^κ_g} Q_κ(x)`；样本形状的兜底输出可满足契约 C，但不属于验证排序池。
- **成本模型**：`C_search = C_profile/probe + C_proposals + C_execution + C_ensemble + C_control/memory`，**包含失败工作**；并行资源占用 ≠ 墙钟时间。

### 2.2 搜索状态与三种执行剖面

- **公共状态**：`S_g = (P_g, A_g, K_g, π_g, R_g)` —— 活跃已评估种群、可复用档案、会话记忆与检索上下文、变异算子分布、剩余预算。执行日志与档案 A_g **分离维护**，失败候选留在日志中。
- **三种剖面（Table 1）**：
  - **Multi-island**：多岛（通用代码 / 树集成 / 神经网络种群），岛内锦标赛选择、代码变异与交叉、Pareto 合并。
  - **Nested**：结构化流水线 + 可选代码候选；诊断干预、适应度—子代数量父代采样、算子信用、档案复用、跨运行经验。**完整自适应策略在此剖面**。
  - **Benchmark**：注册式模态算子与有界配置变体；可比验证前沿、假设探针、预测对齐、终端基准评分。

### 2.3 委员会、编排与初始证据

- **五类角色（Table 2）**：Discovery Driver（下一实验、紧迫性、可执行提案、低成本机会）、Methodology Advisor（问题形式化、方法适配度、置信度）、Memory Keeper（既有发现、已试方法、失败路线、未解问题）——**前三个常驻**；ML Strategist（模型族、特征干预、验证设计）、Code Reviewer（实现缺陷、统计错误、泄漏风险）——**后两个轮换**。
- 合并：`U_r = M({u_{e,r} : e ∈ C_r})`。委员会输出**仅为建议**，真正改动产物的操作由专家与注册工具执行。
- **初始化**：盘点表格、媒体、档案、辅助科学文件与样例提交，产出数据剖面；**假设（hypothesis）**把观察连接到候选路线，并指定前置条件、预期产物、晋升判据与探针/执行预算；**探针**检验路线适用性（几何需辅助文件覆盖、关系匹配需可识别对应、溯源匹配需实测精度与覆盖率）。

### 2.4 定向变异：从父代证据到子代程序

- 诊断记录 `η_x` 可含验证残差、分数据段错误、训练—验证差距、折间波动、特征缺口、与其他候选的预测相关性。
- **中观层评论器**解读诊断，**架构师**转为编辑指令与变异算子偏置。算子 o 的变异 = 提案 + 应用：
  - `δ ~ G_o(· | u_x, η_x, U_r, K_g, T)`，`u'_x = μ_δ(u_x)`。
- **代码模式**：LLM 接收父程序、相关诊断、允许编辑范围，返回改动代码；**流水线模式**：对类型化字段做插入/删除/替换/修改。未改动组件被继承。
- **五类变异（Table 3）**：配置变异、流水线变异、诊断式代码变异、程序交叉、集成变异。各自须独立确立可执行性与测量行为；**父代分数不会被当作子代适应度**。
- **概念区分**：新草案（无指定父代）、变异（扩展一个父代）、交叉（以多个父代为条件或转移兼容组件）、重启（平台期后恢复探索）；"受两个程序启发的代码提案" ≠ 字面基因交换 ≠ 预测平均。
- **准入 vs 繁殖成功**：可准入的子代不必优于父代（可为多样性、质量—复杂度权衡、集成而保留）。共享协议下的观测改进：`Δ_κ(x', x) = Q_κ(x') − Q_κ(x)`——**记录一次测量比较，不是对其他随机种子或未见数据的保证**。

### 2.5 选择、档案与嵌套调度

- **父代采样**（兼顾质量与谱系多样性）：
  - `w_i = sigmoid( λ (Q_i − Q̄) / max(s_Q, s_cv, ε) ) · 1/(1 + n_i)`，`p_i = w_i / Σ_j w_j`。
  - `n_i` 为已用子代数，用于**折扣重复使用的父代**（繁殖多样性与预测多样性、科学新颖性相互独立）。
- **种群与档案更新**（保护精英 E_g）：
  - `P_{g+1} = E_g ∪ Survive_ρ(P_g ∪ V^κ_g)`；`A_{g+1} = ParetoCap_ρ(A_g ∪ P_g ∪ V^κ_g)`。
  - **执行轨迹**（记录发生了什么）与 **Pareto 档案**（存储可复用候选）目的不同。
- **三个时间尺度**：宏循环（检索任务相关经验、调整热启动）、中观循环（周期性或平台期/高方差时触发诊断、发出定向变异、重分配策略）、微观循环（评估—选择—变异—记录）。降折筛选可限制昂贵全评，但**筛选分数不可替代全评适应度**。

### 2.6 算子信用与持久记忆

- **相对父代信用**：`b_t ∈ {0,1}` 表示是否通过配置的父代改进门（全评子代用配对折级证据；未改进或被筛选拒绝得 0）。
- 经验均值 `μ̂_o(g)`（未尝试算子用乐观先验 `μ_prior`），导出权重：
  - `π_{g+1}(o) = max{ε_π, μ̂_o(g)+ε} / Σ_j max{ε_π, μ̂_j(g)+ε}`。
  - 下界作用于**未归一化权重**，不意味着 `π_{g+1}(o) ≥ ε_π`；导出权重归一化经验信用，与 bandit 维护的 UCB 统计量不同。
- **明确的统计学警示**：配对折门是**搜索启发式**而非确证性统计检验；交叉验证折共享训练样本，且大量自适应选择的子代被比较，**朴素独立性论证不成立**。
- **三层经验存储**：算子奖励（改变局部变异分布）、会话记忆（Memory Keeper 压缩后进入后续委员会）、**任务索引的持久库**：
  - `L_{j+1} = L_j ∪ {(φ(T_j), ℓ_j)}`，`K_0(T') = Retrieve_k(L_{j+1}, φ(T'))`。
  - 相似度加权检索提供有界上下文与策略先验；失败策略可降低未来偏好但**不使其不可行**；检索到的程序必须在新任务契约下重评。

### 2.7 预测重组与最终化

- **预测注册表**保留合格候选的折外/留出数组及其行、目标、类别、协议元数据。**仅形状相同不够**：类别标签不能当概率平均，重排行不能按位置对齐。
- **凸混合**：`Y_w = Σ_j w_j Y_j`，`w_j ≥ 0`，`Σ w_j = 1`；若各 Y_j 行是概率向量，则 Y_w 行仍非负且和为 1（精度与校准分别评估）。
- **集成采纳门控**：仅当 `Q_κ(e) > Q_κ(x*) + τ_ens`（τ_ens > 0）时采纳集成，否则保留单一在位者。该门控**不能使集成选择数据变成独立测试集**——重复选择候选、权重或元学习器会过拟合内部验证。
- **执行记录与终端评分**：变异记录中"指令"与"实际代码/配置改动"分列（后者标识实际执行内容，前者解释搜索意图）。Benchmark 剖面默认禁用官方评分；**开发模式**允许评分反馈影响后续工程运行，**评估模式**将评分视为冻结运行的终端操作。
- **Algorithm 1 六步**：① 剖析任务并检索经验/热启动 → ② 运行委员会、路由专家工作、探测路线前置条件 → ③ 执行初始候选并保留全部执行记录 → ④ 循环（选父代/诊断触发→提案变异并记录→筛选与全评→准入与更新档案→更新算子信用并回传委员会）→ ⑤ 搜索兼容预测的集成并应用最终化规则 → ⑥ 冻结程序与产物、蒸馏经验入库、仅在最终选择后按需调用外部评分器。

- **确认程序是混合的**：可以是新训练的随机种子、独立进程执行，或**预测文件的精确重放**——因此"三列"并非完全独立重复的完整搜索。
- **统计量**：`R_campaign = (1/22) Σ_t 1{b_t ∈ {gold, silver, bronze}}`，为活动记录结果汇总，**不是冻结智能体的 pass@1 估计**，原始指标值不跨任务平均。
- **对比方法**：**论文未做与 MLE-STAR / MARS 等的同条件对照实验**，也未做组件消融。相关工作仅作定性定位。
- **代表性程序（Table 5）**：
  - **NOMAD**：解析晶格向量、原子坐标与种类，导出晶胞体积、密度、晶格范数、物种计数
