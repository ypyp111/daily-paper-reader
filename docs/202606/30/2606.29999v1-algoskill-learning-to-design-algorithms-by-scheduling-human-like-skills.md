## 摘要
从自然语言的问题描述中设计一个算法，需要识别问题结构、阅读约束条件、选择合适的范式、检查正确性以及优化复杂度。现有的大语言模型（LLM）方法通常依赖于直接生成或通用的自我改进，使这些步骤变得隐式。我们提出AlgoSkill，它将算法设计建模为对类型化的算法技能库进行顺序决策，包括抽象化、约束分析、状态设计、数据结构选择、证明检查、反例构造和复杂度优化。一个学习到的调度器从当前设计状态中提出技能，而蒙特卡洛树搜索（MCTS）控制器则利用来自编译、测试、压力测试和复杂度分析的验证反馈来探索技能序列。在竞争性编程和组合优化基准上的实验表明，AlgoSkill相比于直接LLM生成、思维链提示、自我改进以及无类型技能的MCTS均有提升。消融实验显示，类型化技能、基于验证的修复以及基于搜索的调度各自对性能有贡献。这些结果支持将自动算法设计视为验证引导的技能调度而非一次性代码生成。

## Abstract
Designing an algorithm from a natural-language problem statement requires identifying the problem structure, reading constraints, choosing a suitable paradigm, checking correctness, and refining complexity. Existing large language model (LLM) methods often rely on direct generation or generic self-refinement, leaving these steps implicit. We propose AlgoSkill, which models algorithm design as sequential decision-making over a typed library of algorithmic skills, including abstraction, constraint analysis, state design, data-structure selection, proof checking, counterexample construction, and complexity refinement. A learned scheduler proposes skills from the current design state, while a Monte Carlo Tree Search (MCTS) controller explores skill sequences using verification feedback from compilation, testing, stress testing, and complexity analysis. Experiments on competitive programming and combinatorial optimization benchmarks show that AlgoSkill improves over direct LLM generation, chain-of-thought prompting, self-refinement, and MCTS without typed skills. Ablations show that typed skills, verification-based repair, and search-based scheduling each contribute to performance. These results support treating automatic algorithm design as verification-guided skill scheduling rather than one-shot code generation.

### 论文提出的方法论

- **核心思想**：
    - AlgoSkill 将算法设计过程形式化为一个序列决策问题。它维护一个包含设计状态（Design State）的结构，并通过一个“技能调度器”在**一个类型化的算法技能库**中选择和排序技能，逐步构建最终的算法。
    - 调度过程受到一个**验证器**的引导，该验证器提供来自编译、单元测试、压力测试和复杂度分析的反馈信号。学习过程则通过强化学习来优化调度策略。

- **关键技术细节**：
    1.  **问题形式化**：
        - 问题实例 `q = (D, I, O, K, M)` 包含自然语言描述、输入/输出格式、约束条件和评估指标。
        - **设计状态** `st` 包含了问题的解析信息、当前算法计划、代码片段、复杂度估计、失败信号（测试结果、反例）以及已使用的技能轨迹。
        - 任务目标是学习一个策略 `πθ`，使其能从当前状态中选择合理的技能，最终最大化验证器给出的奖励。

    2.  **技能库 (Algorithmic Skill Library)**：
        - 定义了一个包含 **20种类型化技能** 的库，如：`oabs`（问题抽象）、`oconstraint`（约束分析）、`obrute`（暴力解法构建）、`ostate`（状态设计）、`ods`（数据结构选择）、`ocomplex`（复杂度优化）、`ocounter`（反例构造）等。

    3.  **技能调度与搜索 (Skill Scheduling and Search)**：
        - **有效技能过滤 (Valid-Skill Filter)**：根据当前状态，基于技能的前置条件自动屏蔽不适用的技能，缩小搜索空间。
        - **学习到的技能策略 (Learned Skill Policy)**：使用一个神经网络 `fθ` 为当前状态下的所有有效技能打分，形成策略 `πθ(o | st)`。
        - **MCTS 搜索控制器 (MCTS Search Controller)**：采用蒙特卡洛树搜索（MCTS）来探索技能序列，而非仅使用贪心策略。MCTS 使用上置信界（UCB）公式在探索与利用之间取得平衡，选择技能节点，进行扩展、模拟（解码出算法并通过验证器评估），并反向传播奖励（`Q(s, o)`）。
        - **符号复杂度追踪 (Symbolic Complexity Tracking)**：算法设计时，通过操作图 `Ga` 进行符号化复杂度估计，并与后续拟合的运行时复杂度进行比较，若存在显著差异则施加惩罚。

- **算法流程**：
    - **输入**：问题 `q`，技能库 `O`，调度器 `πθ`，验证器 `V`。
    - **初始化**：根据问题构造初始状态 `s0`。
    - **迭代搜索**：对于每次搜索预算 `B`：
        1.  **选择 (Selection)**：从根节点 `s0` 开始，根据 MCTS 的 UCB 公式选择最优技能。
        2.  **扩展 (Expansion)**：应用选定的技能，生成新状态 `s′`。
        3.  **模拟 (Simulation)**：解码当前状态得到候选算法 `a′`，通过验证器 `V` 获得奖励 `R`。
        4.  **反向传播 (Backpropagation)**：将奖励 `R` 反向传播，更新路径上状态-技能对的 `Q` 值和访问次数。
    - **输出**：返回在搜索树中找到的最佳已验证算法。

- **训练**：
    - 使用**策略梯度强化学习**（如 `REINFORCE`）训练调度器 `πθ`，奖励函数（`R`）分解为正确性、效率、可解释性、修复成功和冒险惩罚等多个方面，提供了比简单“通过/失败”更细粒度的反馈信号。
    - 采用**技能信用分配 (Skill Credit Assignment)** 机制，不仅计算轨迹级别的奖励，还计算单步技能选择带来的局部变化（`∆t`），以更精确地奖励或惩罚特定技能。

### 不足与局限

1.  **技能库覆盖的局限性**：AlgoSkill 的性能高度依赖于预定义技能库的完整性和质量。对于需要全新或非常规技能的问题，框架可能无法有效处理。
2.  **计算成本较高**：MCTS 搜索过程引入了额外的 token 消耗和计算延迟，相比于直接生成，开销更大。尽管进行了 token 效率分析，计算资源的消耗仍是实际应用中的障碍。
3.  **验证器的局限性**：验证器（基于编译、测试、复杂度检查）可能无法覆盖所有边界情况或逻辑错误，尤其是对于一些复杂的形式化证明，这会引入“奖励黑客”或漏检的风险。
4.  **实验范围有限**：所有实验均集中在竞争性编程和组合优化任务上，**未涉及更广泛的现实软件工程场景**（如需求分析、架构设计、大型系统重构、科学计算等）。因此，其通用性在更复杂的软件工程场景中尚待验证。
5.  **训练依赖性**：调度器需要针对验证反馈进行强化学习训练，这意味着可能需要一个高质量的验证环境或大量的在线交互样本，这在某些现实场景下可能难以获得。
