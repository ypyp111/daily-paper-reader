## 摘要
智能体技能是一种新兴方式，用于扩展大语言模型智能体，使其具备可按需加载的可复用程序性知识。Anthropic 引入了智能体技能，并将该格式作为开放规范发布，得到了多种智能体工具的支持。本文认为，技能是一种软件制品，其构建应遵循软件工程原则，但需注意若干限定：单一职责、接口与实现分离、低耦合、在共享令牌预算内的经济性，以及用行为评估替代确定性测试。以 Claude Code 作为参考实现，本文描述了技能的结构、其内容如何分阶段加载，以及如何编写用于选择的描述。本文还将技能与开发者可用于塑造智能体行为的其他机制进行了对比，例如项目记忆文件、斜杠命令、子智能体、外部工具连接和钩子，并给出了一条基于谁决定机制运行以及该机制提供何种保证的规则来在这些机制之间进行选择。随后，本文提出了一种以评估为导向的编写流程，一套编写过程中常见的模式和故障，以及使用第三方技能所带来的信任问题。我们以 UML 类图风格展示了所进行的比较、加载模型、技能的解剖结构、每种机制在会话中的相对位置，以及技能和钩子在会话期间的触发点。

## Abstract
Agent Skills are an emerging way to extend large language model agents with reusable procedural knowledge that the agent loads on demand. Anthropic introduced Agent Skills and published the format as an open specification supported across several agent tools. This note argues that a skill is a software artefact and that its construction should follow software-engineering principles, with qualifications: single responsibility, separation of interface from implementation, low coupling, and economy in a shared token budget, together with behavioural evaluation in place of deterministic testing. Using Claude Code as the reference implementation, it describes how a skill is structured, how its contents are loaded in stages, and how to write the description on which selection depends. It places skills against the other mechanisms a developer can use to shape agent behaviour, like project memory files, slash commands, subagents, external tool connections, and hooks, and gives a rule for choosing between them based on who decides that a mechanism runs and what guarantee it provides. It then sets out an evaluation-driven authoring process, a set of patterns and faults commonly encountered in authoring, and the trust question raised by using skills from third parties. We illustrate the comparison drawn in UML class style, the loading model, the anatomy of a skill, the relative position of each mechanism, and the points at which skills and hooks act during a session.

# 论文详细总结

## 1. 核心问题与整体含义

- **背景与动机**：大语言模型智能体（agent）正在成为通用任务执行者，但如何为其注入可复用的程序性知识、并让智能体在合适时机按需加载，仍缺乏系统性的工程方法。Anthropic 推出的 Agent Skills 提供了一种开放格式（SKILL.md + 辅助文件），但官方文档更多描述“是什么”，缺少关于“如何构建”的工程原则。
- **核心论点**：**技能（Skill）是一种软件制品**，其编写应遵循软件工程原则，但必须针对智能体的特殊性加以调整——尤其是**不能用确定性测试**，而应使用**行为评估**。
- **整体含义**：本文为技能编写提供了从结构设计、机制选型到评估迭代的完整视角，帮助开发者将技能从“临时提示词”提升为受控的、可维护的软件组件。

## 2. 方法论

### 2.1 核心思想：技能即软件制品

- 技能 = 普通文件（SKILL.md + 脚本 + 参考文档），可纳入版本控制；
- 技能具有**接口**（描述 description）与**实现**（正文 body + 捆绑文件）；
- 技能可组合（捆绑资源、调用工具、调用其他技能）；
- 技能可能失败（未被选中、被选中但未正确执行），因此需要工程化对待。

### 2.2 适用软件工程原则（带有限定）

- **单一职责**：一个技能只服务一类任务，使描述更聚焦，提高模型匹配率；
- **接口与实现分离**：选择器只读 metadata（name + description），正文在选中后才加载，遵守“分阶段加载”；
- **低耦合**：技能之间避免内部依赖，依赖关系要显式、少量；
- **Token 预算经济性**：上下文窗口是共享硬资源，技能内容要“每 token 都有价值”；
- **行为评估替代确定性测试**：技能没有隔离行为，需通过“模型+技能”在任务上的通过率来评估，而非单元测试断言语义。

### 2.3 技能结构与分阶段加载

- **结构**：一个目录含 SKILL.md（YAML frontmatter + Markdown body），可选捆绑参考文件、脚本、模板；
- **Frontmatter 约束**：name ≤64 字符（小写字母/数字/连字符，禁止 XML 标签和保留词 claude/anthropic）；description ≤1024 字符，禁止 XML 标签；
- **三级加载模型**：
  1. **Level 1 元数据**：所有已安装技能的 name+description 在会话开始即常驻，约 100 tokens/技能；
  2. **Level 2 正文**：模型判断任务匹配后读取 SKILL.md，正文应 <500 行（约数千 tokens）；
  3. **Level 3 捆绑文件**：按需读取/执行，未访问前不消耗 token；
- **调用路径**：
  - 自动调用：模型按描述概率性触发；
  - 显式调用：用户按名称调用，确定性触发，可通过 frontmatter 禁用自动调用。

### 2.4 描述编写策略

- 用第三人称；
- 同时说明“做什么”和“何时用”；
- 包含任务真实场景中的具体术语（如“从两个版本标签之间合并的 PR 生成发布说明”）；
- 描述是文档也是触发条件，质量直接决定选择率。

### 2.5 技能与其它机制的选择规则

- 区分机制的两个关键问题：**谁决定运行**（模型/用户/运行时）与**提供什么保证**（advisory 至 blocking）；
- 机制对比表（Claude Code 实现）：
  - **记忆文件 CLAUDE.md**：运行时始终加载，提供常驻上下文，适合短、通用、需每轮可见的指令；
  - **技能**：模型或用户触发，分阶段加载程序性知识，适合模型可自主发现的领域流程；
  - **斜杠命令**：用户触发，保存的提示词，适合用户精确控制时机；
  - **子智能体**：模型或用户委托，独立上下文窗口，适合隔离执行；
  - **外部工具（MCP）**：模型调用，连接外部服务，适合在真实世界操作；
  - **Hook**：运行时在生命周期事件上触发，可阻塞动作，适合“每次必须发生”的保证；
  - **插件**：用户安装，组合上述机制分发。

- **技能 vs Hook 的决策规则**：依赖判断、随上下文变化、编码领域程序 → 技能；必须每次事件发生时无条件执行、需要防止某动作 → Hook。仅 Hook 能提供确定性阻塞保证，不要用技能正文“语气强硬的指令”替代 Hook。

## 6. 主要结论与发现

- **技能确实是软件制品**，应使用软件工程纪律来构建，但需以行为评估替代确定性测试；
- **分离接口与实现**在技能中是天然的分阶段加载机制：只有描述被常驻，正文和捆绑文件按需进入上下文；
- **机制的选型规则**极简而实用：由“谁决定运行 + 提供何保证”决定——模型决定且 advisory 的放技能；运行时决定且 blocking 的放 Hook；用户决定且按需执行的放斜杠命令；
- **内存文件是特例**：运行时总是加载，但仅提供 advisory 效果；
- **评估驱动的编写流程**：先写评估，再写最小实现，用双模型实例（起草 + 测试）迭代；
- **第三方技能必须被审查**：技能可携带指令、脚本和外部链接，智能体会以其权限执行，因此应按软件依赖对待。

## 7. 优点
