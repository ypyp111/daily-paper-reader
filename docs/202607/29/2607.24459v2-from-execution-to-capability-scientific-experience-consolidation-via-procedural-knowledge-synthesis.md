## 摘要
大语言模型越来越多地解决科学计算任务，但来自一个问题的可执行反馈很少能转化为解决后续问题的持久能力。我们研究科学计算经验巩固：将经过验证的运行经验转化为可迁移的程序性知识和持续的模型改进。这一设定面临两个挑战：轨迹衍生的产物可能编码了特定于源的修复而非跨任务的计算机制；较弱的靶标模型可能无法操作化一个原本有效的抽象过程——即抽象-执行鸿沟。我们引入SciConsolidate，它对比验证过的成功与失败以归纳跨任务程序，通过开发-验证门控选择它们，并使用基于失败信息且无答案的查询合成来扩展巩固数据，而无需预先存在的参考答案。由于靶标模型可能无法直接执行这些抽象，一个更强的模型将它们具体化为可执行代码监督，用于标准的、无程序的监督微调；一个匹配的无程序教师分支则隔离了程序指导的价值。在SciCode上，运行时程序注入使Qwen3.6-27B提升了+3.85/+6.26子步骤/主问题分数，但对Qwen3.5-9B几乎没有产生主问题上的总体提升，为抽象-执行鸿沟提供了操作性证据。经过程序指导的具体化后，9B学生模型在无程序部署下比无程序监督微调控制组提升了+3.89/+6.25分，比原始9B模型提升了+5.62/+11.25分。这些结果为科学计算建立了一条从经验到能力的路径，并为扩展自我改进的科学辅助提供了实用起点。

## Abstract
Large language models increasingly solve scientific-computing tasks, but executable feedback from one problem rarely becomes durable capability on subsequent problems. We study scientific-computing experience consolidation: converting verified runtime experience into transferable procedural knowledge and persistent model improvement. This setting presents two challenges: trajectory-derived artifacts may encode source-specific repairs rather than cross-task computational mechanisms; and a weaker target model may be unable to operationalize an otherwise valid abstract procedure - an abstraction-execution gap. We introduce SciConsolidate, which contrasts verified successes and failures to induce cross-task procedures, selects them through a development-validation gate, and uses failure-informed, answer-free query synthesis to expand the consolidation data without requiring pre-existing reference answers. Because the target model may not directly execute these abstractions, a stronger model concretizes them into executable code supervision for standard, procedure-free SFT; a matched no-procedure teacher branch isolates the value of procedural guidance. On SciCode, runtime procedure injection improves Qwen3.6-27B by +3.85/+6.26 sub-step/main-problem points, but yields almost no aggregate main-problem gain for Qwen3.5-9B, providing operational evidence of the abstraction-execution gap. After procedure-guided concretization, the 9B student improves under procedure-free deployment by +3.89/+6.25 points over the no-procedure SFT control and by +5.62/+11.25 over the original 9B model. These results establish an experience-to-capability pathway for scientific computing and provide a practical starting point for scaling self-improving scientific assistance.

## 1. 论文的核心问题与整体含义（研究动机和背景）

大语言模型（LLM）在科学计算任务中（如数值分析、仿真、公式推导等）已取得显著进展，但一个关键瓶颈始终存在：**模型从某次执行中获得的验证反馈（成功或失败）几乎无法转化为应对后续问题的持久能力**。例如，模型在解决“求解偏微分方程”时因接口错误而失败，即便给出了正确修复，下一次遇到相同错误模式时仍会重复犯错。这种“经验固化不足”不仅浪费了宝贵的执行证据，也限制了科学计算智能体的持续自我改进。

论文将这一问题形式化为 **“科学计算经验巩固”（Scientific-Computing Experience Consolidation）** ，即：如何将经过运行时验证的执行经验转化为可跨任务迁移的程序性知识（Procedural Knowledge），并最终沉淀为模型参数的持久能力提升。该问题面临两大挑战：

- **轨迹伪影可能编码源特定修复而非跨任务计算机制**：从单一问题提取的修复或成功模式可能只对当前领域有效，无法泛化到其他科学领域。
- **抽象-执行鸿沟（Abstraction–Execution Gap）**：即使提炼出有效的抽象程序（如“始终在数组操作前检查维度”），能力较弱的模型可能无法将其具体化为可执行的代码行为，而强模型则能做到。

论文旨在通过系统化的流程（经验→抽象程序→具体化监督→模型更新）打通从“单次执行反馈”到“内部化能力”的路径，为构建自我改进的科学助手提供实用起点。

## 2. 论文提出的方法论

**核心思想**：通过数据驱动的管道，将目标模型的已验证运行时体验（成功和失败轨迹）转化为经过验证的家族级程序性知识，再借助更强模型将程序具体化为可执行代码监督，最终通过标准SFT将能力内化到目标模型中。整个过程无需在推理时提供外部程序。

**关键技术细节**（按流程顺序）：

1. **任务结构化与拆分纪律**：
   - 为每个任务分配描述符向量 z(x)，包括领域、子领域、任务类型、难度估计和失败族标签。
   - 将任务集划分为互斥的 Dtrain（经验收集、知识提炼、种子数据）、Dval（开发验证门控）、Dtest（冻结保留集，不用于任何迭代决策）。

2. **验证经验收集与失败归因**：
   - 在 Dtrain 上对目标模型 Mθ 进行多次尝试（K次），通过可执行评估分离成功/部分成功/失败。
   - 比较成功与失败轨迹，识别跨任务、跨领域的重复操作失败轴（如形状不匹配、接口误用、依赖流中断），形成失败族 {Fl}。
   - 基于配对证据归纳每个族的初始程序 s(0)_l，描述激活条件、决策规则、终止条件和高危反模式。

3. **验证门控的程序知识综合（Validation-Gated Procedural Knowledge Synthesis）**：
   - 程序视为版本化知识工件，迭代优化。候选程序需在 Dval 上通过效用门 G 的评估（如配对改进）才被采纳。公式：若 G(Dval, s̃(t+1)_l) > G(Dval, s(t)_l) 则升级，否则保留旧版。
   - 保留最佳版本 s*_l，确保程序具备跨任务泛化性而非仅过拟合源失败。

4. **知识引导的科学计算查询合成（Knowledge-Guided Query Synthesis）**：
   - 由于原始任务集小且分布集中，利用扩展生成器 produce 新问题，同时控制种子来源浓度、领域/任务类型比例、失败族覆盖及目标模型行为回放。
   - 无需预先存在的参考答案；生成的新任务附带可执行检查（用于后续过滤）。
   - 平衡后的查询池 Qsyn 与原始训练池合并为 Qsft。

5. **程序引导的知识具体化（Procedure-Guided Concretization）**：
   - 使用更强模型 MT（27B）作为“程序具体化器”。对于每个查询 x，若属于族 Fl，则向 MT 提供 x + s*_l 生成具体代码解决方案 yT。
   - 学生输入不含程序，仅在训练时学习 (x, yT)。对于原始开发-训练任务，仅保留验证通过的解；对于合成查询，使用本地可执行检查过滤。
   - 为隔离程序指导的效应，构造**无程序控制分支**：MT 不提供程序 s*，仅用相同查询生成 y0_i，得到控制数据集 D0_sft。两个分支的构造流程完全一致，仅教师提示中是否包含程序不同。

6. **最终训练与评估**：
   - 目标模型通过标准SFT训练（在 D_sft 或 D0_sft 上），推理时不提供任何外部程序。
   - 比较“程序指导SFT学生” vs “无程序SFT学生” vs “原始9B基础模型”，在 SciCode 上报告子步骤正确率和主问题正确率。

## 6. 论文的主要结论与发现

1. **抽象-执行鸿沟的存在**：同样一组验证过的程序知识，对27B模型推理时直接注入带来+3.85/+6.26的提升，但对9B基础模型几乎无增益（主问题0.00%提升，子步骤-0.30%）。这证实了程序的有效性依赖于消费模型的能力，弱模型无法可靠地将抽象程序操作化为可执行行为。

2. **鸿沟可通过程序引导具体化桥接**：即使9B模型不能直接使用程序，但通过强模型27B将程序作为引导生成具体代码监督，9B学生模型在无程序部署下比无程序SFT控制组提升+3.89/+6.25（聚合），比原始9B提升+5.62/+11.25。保留集上的增益为正（+1.46/+3.33），表明泛化能力有所提升。

3. **经验到能力的完整路径可行**：论文演示了Mθ → 执行 → E → 抽象 → S → 引导合成 → D_sft → 学习 → Mθ' 的单次通道的有效性，为科学计算智能体的自我改进提供了可操作的起点。

4. **增益分布不均匀**：模拟和科学计算任务提升明显；阵列/数值推理和逻辑/依赖流失败族有积极改善；但数值方法任务类型和规范/接口族仍为弱项，留待后续迭代。

## 7. 优点

1. **问题定义清晰新颖**：首次将科学计算中的“经验巩固”形式化为从执行证据到程序知识再到模型能力的完整闭环，区别于单纯技能重用或运行时提示，具有明确的可操作性。

2. **精心控制的数据分割**：训练/验证/保留集的严格划分，以及开发验证门控，防止程序或数据混合物过拟合源任务，提升了结论的可靠性。

3. **消融设计严谨**：通过“无程序SFT控制组”并确保管道匹配（相同查询池、生成预算、构造协议），隔离了程序指导的增值效应，避免将强教师模型的通用能力混淆为程序知识带来的增益。

4. **细粒度多维度分析**：从任务类型、科学领域、失败族、运行时注入效果等多个粒度进行诊断，不仅报告总体提升，也指出弱项，为后续工作指明方向。

5. **案例详实**：附录包含丰富的具体案例（如共轭梯度求解器、Gram-Schmidt正交化、Langevin动力学等），直观展示模型从失败到成功的行为变化。

6. **实用导向**：最终训练使用标准SFT，部署时不需运行时程序，符合实际应用中对低开销、易维护性的需求。

## 8. 不足与局限

1. **实验覆盖范围窄**：仅基于SciCode一个基准（80主问题），未在更大规模或更多样化的科学计算环境（如CFD、FEM、工具使用、真实实验）中验证，通用性存疑。

2. **抽象-执行鸿沟的因果证据不足**：9B/27B的对比使用了不同预训练版本（Qwen3.5 vs 3.6），不能完全排除模型架构、训练数据差异等混淆因素。需要更系统的缩放研究和受控的程序复杂度实验才能确定因果机制。

3. **知识范围窄**：提炼的程序知识限于计算实践（接口纪律、数组推理、依赖流等），不涉及新科学规律发现、自主假设生成或完整实验科学周期，离“AI科学家”目标有差距。

4. **依赖外部强模型**：错误标注、程序归纳和解决方案生成均依赖比目标模型更强的外部模型（GLM-5.1和27B），尚未实现完全自给自足的自我改进。如果外部模型不可用或成本过高，则管道失效。

5. **合成查询验证有限**：合成任务不具备预先参考答案，仅靠本地可执行检查过滤，可靠性取决于检查的覆盖率和设计质量。在弱验证场景下（如无确定性测试），生成监督的质量无法保证。

6. **最终答案监督而非推理监督**：训练仅使用最终代码答案，丢弃了具体化器的推理轨迹，可能丢失有用结构，也无法处理需要多步推理的任务。论文指出推理保留是未来工作。

7. **非均匀转移与可能负干扰**：增益主要来自模拟和某些失败族，数值方法和接口族仍为弱项。后续迭代需要在不破坏已巩固行为的前提下处理残留失败，但论文未研究干扰问题。

8. **未探索多轮迭代**：实验仅演示单次通过，没有用更新后的模型重复整个管道，因此无法评估可持续自我改进的潜力或风险（如灾难性遗忘、反馈循环放大偏差）。
