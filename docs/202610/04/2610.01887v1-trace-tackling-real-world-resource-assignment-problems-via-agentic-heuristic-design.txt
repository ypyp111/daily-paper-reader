# ABSTRACT 

Dynamic resource assignment, the real-time allocation of task streams to hetero-geneous processing nodes, is the backbone of modern computing infrastructure. While learning-based schedulers excel in research, industrial deployments still rely on hand-written rules that operators can read, audit, and execute within tight latency budgets. LLM-based Automatic Heuristic Design (AHD) promises to automate writing such rules. However, existing AHD frameworks were developed for combinatorial problems fully specified to the LLM, and they learn only from a scalar fitness score. In real systems, the behaviour that determines a good heuristic, such as processor speeds or power consumption, is unknown a priori: the score reveals which heuristic performs better, but not why . This missing information is recorded in the system logs that every evaluation produces. Exploiting it is non-trivial: logs are massive and noisy, the relevant signals depend on the objective, and their content and format vary across hardware and software stacks, so they can neither be fed to an LLM as is nor processed by a fixed parser. We propose TRACE, which couples an evolutionary AHD loop with an agentic knowledge-extraction workflow. A Reasoner agent analyzes the log schema in light of the objective and formulates hypotheses about the system dynamics; a Coder agent writes and executes schema-specific code to test them, producing insights or executable tools for the evolved heuristics. We evaluate TRACE on a synthetic cloud benchmark and a 5G vRAN scenario built from industrial testbed measurements and operational traffic traces. TRACE consistently outperforms state-of-the-art AHD methods in resource assignment problems and yields more auditable heuristics at under 2% overhead. 

# 1 INTRODUCTION 

Dynamic task scheduling is the operational backbone of modern industrial infrastructure: incoming streams of tasks must be allocated in real time to a limited set of processing nodes. In cloud computing data centers, orchestrators assign heterogeneous workloads (e.g., AI training jobs or virtual machines) across thousands of servers (Hosseini Shirvani, 2024; Khallouli & Huang, 2022). In wired and wireless networks, routers and base stations act as computing nodes that continuously process streams of data packets (Schiavo et al., 2024; Aslan et al., 2024). Inefficient scheduling leads to increased latency, energy waste, and service violations. Despite decades of research, production schedulers remain predominantly hand-written rules. Classi-cal formulations such as the Dynamic Job-Shop Scheduling Problem (DJSSP) (Liu & Huang, 2023; Zhang et al., 2022) assume known processing times and unbounded queues, which rarely match deployed systems. Deep reinforcement learning (DRL) relaxes these assumptions (Mao et al., 2016; Li et al., 2023), but its policies are hard for operators to inspect, certify, and modify, and can degrade under the simulation-to-deployment shift. Operators therefore favor rules they can read, audit, and execute within tight latency budgets (Ding et al., 2020). LLM-based Automatic Heuristic Design (AHD) can automate the writing of such rules. Frameworks such as FunSearch (Romera-Paredes et al., 2024), EoH (Liu et al., 2024), ReEvo (Ye et al., 2024), HSEvo (Dat et al., 2025), and AlphaEvolve (Novikov et al., 2025), which has even improved a produc-tion data-center scheduling heuristic, evolve programs in a loop: an LLM proposes code, an evaluator returns a scalar fitness, and the best candidates seed the next generation. These approaches, however, share a blind spot: the only feedback is a scalar . This is largely sufficient on the combinatorial benchmarks where AHD has been developed (e.g., TSP, flow-shop, or online bin packing), because the LLM is given the full problem specification. In real resource-assignment systems, instead, the quantities that determine which heuristic is good, such as per-node processing times, energy profiles, and queue capacities, are unknown to the designer a priori . Scalar-feedback search can learn which 

heuristic scores better, but not why .Consider a cluster in which one node is much faster than the rest but also far more power-hungry. An energy-efficient policy should use this accelerator for very heavy tasks or when the system is saturated, which requires knowing each processor’s performance and energy profile. Scalar-feedback search can only stumble upon this behavior by trial and error, yet the needed information is recorded in the system logs during every evaluation. Our key insight is that these logs can turn heuristic search from blind trial and error into informed, data-driven design (Fig. 1). Exploiting logs is nevertheless non-trivial. ( i) Raw logs can reach gigabytes and are dominated by irrelevant entries, so they cannot simply be placed in an LLM prompt. ( ii ) What is relevant depends on the objective: minimizing latency or energy calls for different metrics, and which ones matter is often unclear in advance. ( iii ) Logs are heterogeneous in content and format: the available metrics depend on the hardware, and field names, units, and structure vary across systems, so a fixed, hand-written parser does not transfer. Moreover, reflection-based AHD methods (e.g., ReEvo) reason only over the fitness history, not over the system behavior behind it. Extracting useful knowledge thus requires reasoning jointly about the objective and the log schema, and writing code tailored to both. To this end, we propose TRACE, which augments LLM-based AHD with an agentic knowledge-extraction workflow : a Reasoner agent identifies which log information is relevant to the objective, and a Coder 

agent writes and executes code to extract it, producing either an insight into system behavior or a tool. This knowledge is fed back into the heuristic-generation loop to inform each new candidate. We evaluate TRACE on ( i) a synthetic cloud-computing benchmark with up to 50 heterogeneous servers that tests scalability, and ( ii ) an energy-efficient 5G virtualized RAN scenario driven by measurements from an industrial-grade testbed and traffic traces from an operational network. In the cloud benchmark, TRACE is the only method that achieves zero task loss with 50 servers, reducing cost by more than an order of magnitude relative to the best AHD baseline. In the 5G scenario, it matches the carrier-grade reliability of the industry-standard policy (0% loss) while consuming 65% and 25% less energy than the industry standard and SoTA AHD approaches, respectively. We evaluate the auditability of TRACE’s heuristics using an LLM-as-a-judge approach, where they obtained the heuristics highest in semantic grounding and auditability, as their logic is expressed in terms of physical quantities (predicted processing times, per-processor thresholds) rather than the opaque arithmetic the baselines converge to. All these gains come at a 1.9% overhead relative to EoH at an equal generation budget. 2Preprint

We seek g⋆ = arg min g∈G J(g) over a space G of programs, without access to {T (n), R (n), Q (n)}.Instead, the designer can evaluate any candidate g on the system or a simulator. Each evaluation returns the scalar fitness J(g) and an execution log Λ( g) = {(τi, xi, n i, mi)}i, where mi contains the metrics that system S records for task i (e.g., processing time, drop status, queue occupancy, energy). Existing AHD methods search G using only J(g). We study how to also exploit Λ( g). Three challenges make this non-trivial: ( a) |Λ( g)| grows with the number of tasks and evaluations, so logs cannot be placed in an LLM context; ( b) which components of mi are informative about J depends on the instantiation of P, and even informative components are raw per-task records that must be distilled (e.g., into per-node statistics or predictive models) before a heuristic can use them; ( c) the recorded metrics and log format depend on the system, so extraction cannot be fixed in advance. Distilled knowledge may be a textual insight or an executable tool (e.g., a predictor of ti,n ); we allow heuristics to call such tools K, i.e., g ∈ G (K).

# 3 METHODOLOGY 

TRACE exploits both the fitness J(g) and the execution logs Λ( g) of every evaluation. It couples two nested loops (Fig. 2; Algorithm 1): an evolutionary generation loop that proposes and evaluates heuristics, and an Agentic Knowledge Extraction Workflow that runs at the start of each epoch and distills logs into textual insights and executable tools K, exposed to the heuristics through the generation prompt. The design targets the three challenges of Sec. 2: ( a) the LLM agents only see a short log excerpt or the log schema, while the full log is processed by generated code; ( b) hypotheses are formulated in light of the optimization objective and specify how the relevant metrics are distilled into insights or tools; and ( c) the extraction code is written for the log schema of each system. 3.1 HEURISTIC GENERATION LOOP 

The evolutionary backbone of TRACE follows the principles described by Liu et al. (2024). The algorithm database D holds a fixed-size population of heuristics and their fitness. The search runs over epochs e = 1 , . . . , E , each comprising I generation steps j = 1 , . . . , I . The Agentic Workflow converts the log buffer into knowledge in three steps (Fig. 3) that involve three objects: a Diagnostic Hypothesis he, a short natural-language statement of what could be learned from the logs; a Diagnostic Artifact Ae, a program that realizes he on the logs; and the Diagnostic Knowledge Ke obtained by executing Ae. Ke is either a Semantic Insight , i.e., a textual description of a behavioural pattern (e.g., average power per processor), or a Surrogate Model , i.e., a callable estimator of an unknown system quantity. 

Reasoner. The Reasoner agent formulates he from the problem description Π (and thus the objective, challenge b), the current System Information σe−1, and a log excerpt ξ(Λ) , i.e., a few rows with their column names, or the log schema usually provided by the system manufacturer. The requested knowledge type κe alternates between Semantic Insight and Surrogate Model across workflow runs, starting with an insight. To promote diversity, the prompt lists the hypotheses H proposed so far and asks for a different one, following the “propose” prompting strategy of Yao et al. (2023). 

Coder. The Coder translates he into the Diagnostic Artifact Ae, written for the log schema in ξ(Λ) 

(challenge c) and executed in a sandbox on the full buffer Λ (challenge a). For a Semantic Insight, 

Ae prints the facts extracted from the logs. For a Surrogate Model, it fits a low-parameter regression, stores its weights, and defines a predict function with a usage example; the inference cost of such low-complexity models is negligible relative to the decision budget. If execution fails (e.g., syntax error or schema mismatch), the Coder regenerates Ae, up to Mmax attempts.

The Agentic Workflow runs at the start of each epoch until Emax runs have succeeded, i.e., their Diagnostic Artifacts executed; failed runs do not count toward this budget. Afterwards, the System Information is frozen, and the remaining epochs are purely evolutionary. The agents are deliberately asymmetric. The Reasoner, which must reason about latent system dynamics from a log excerpt, uses a frontier reasoning model but is invoked only once per workflow run. The Coder, the Merge step, and the generation loop, which together make thousands of LLM calls, use a lightweight open-weight model. Consequently, the workflow adds less than 2% wall-clock time over EoH at an equal generation budget (Sec. 4.5). Hyperparameters and models are listed in Appendix C, and the effect of the LLM choice is analyzed in Appendix E. 

# 4 EVALUATION 

We evaluate whether TRACE (i) outperforms state-of-the-art AHD methods under the same generation budget, and how this advantage scales with the number of processors (Sec. 4.3); (ii) carries over to a measurement-driven industrial system with a different objective (Sec. 4.4); (iii) at what computational cost (Sec. 4.5); and (iv) whether its heuristics are more auditable (Sec. 4.6). 4.1 EVALUATION USE CASES 

(i) A synthetic cloud computing use case that tests scalability in settings more complex than prior work (Soualhia et al., 2015; Bader et al., 2024; Rosa et al., 2021), e.g., 20 nodes of 5 types with 1-dimensional features and linear processing times in Bader et al. (2024). We consider Scenario 1 

(N = 10 ) and Scenario 2 (N = 50 ), with all servers of different types and d = 5 task features. Why does TRACE outperform the baselines? Its best heuristic in Scenario 1 (Algorithm 1, Appendix I) relies on physical properties of the system: it (i) calls the learned surrogate to estimate processing times, (ii) penalizes fast processors to prevent their saturation, (iii) uses the variance of processing times as a reliability measure, and (iv) balances the load with randomized top-k selection. This knowledge comes from the agentic workflow, which, driven by the Diagnostic Hypotheses in Prompt 13, evolves the System Information prompt (Prompt 4) into one that exposes a callable surrogate, per-processor speed statistics, and the dominant features of each processor (Prompt 14). Scenario. In 5G virtualized Radio Access Networks (vRAN), base station functions run on general-purpose edge clouds, and the computational bottleneck is uplink decoding. Each task is a Transport Block (TB) whose features, i.e., Transport Block Size, Modulation and Coding Scheme, and Signal-to-Noise Ratio, dictate its computational complexity. under a hard 1 ms deadline: TBs not decoded in time are dropped with penalty Γ = 10 (equation 2). Processing times and energy are queried from measurements of an industrial-grade vRAN testbed, and arrivals are replayed from traces of an operational mobile network (Lo Schiavo et al., 2024); details are given in Appendix G. 

Result analysis. Table 2 reports the TB loss rate, mean processing delay, mean energy per TB, and cost. The rule-based policies show how hard it is to meet hard real-time constraints on heterogeneous processors. Random and Oracle-Queue balance the load but lose about 10% of the TBs, as computa-tionally intensive tasks land on slow CPU cores. Oracle-Time achieves 0% loss by always choosing the fastest processor, but it is energy-agnostic: it uses high-power accelerators even for tasks that CPUs could finish in time, yielding the second-highest energy consumption. Among current vRAN deployment policies, CPU-Only (Ding et al., 2020; Foukas & Radunovic, 2021) has the lowest energy but a 27% loss rate during traffic peaks, unacceptable for carrier-grade 5G, whereas HA-Only (the industry standard) guarantees 0% loss and minimal delay through over-provisioning: power-hungry accelerators process every task regardless of complexity, yielding the highest energy consumption. Among AHD methods, we compare against EoH, the log-free counterpart of TRACE and the strongest AHD baseline in the larger cloud scenario, so that the gap measures the value of the logs. EoH finds a zero-loss policy with 35% lower cost than the best fixed policy (0.58 vs. 0.89, Oracle-Time). TRACE also keeps 0% loss while consuming the least energy among zero-loss policies: 64 .9% less than HA-Only and 25 .4% less than EoH (397.89 vs. 533.33 μJ); its higher delay (0.36 ms) is well within the deadline, which is all the objective requires. Since TRACE reduces to EoH without the agentic workflow, this gap is attributable to the knowledge extracted from the logs: a processing-time surrogate, the average energy of each processor, and the dominance of the transport block size on CPU processing time. All methods share the same generation budget, and TRACE’s evolutionary backbone is functionally equivalent to EoH, so the runtime difference between them reduces to the agentic workflow. In an epoch in which it runs, the workflow adds 32 .2 s (Reasoner 22 .5 s, Coder 7.4 s, sandbox 2.2 s) to the 

430 .5 s of heuristic generation and evaluation over the I=150 steps, i.e., 6.95% of the epoch. The workflow runs only until Emax =5 successful executions, after which the System Information prompt is frozen and the remaining epochs are purely evolutionary. Over E=20 epochs, it thus accounts for 161 s out of 2.44 h, a 1.9% wall-clock overhead relative to EoH, which does not grow with the number of processors since the workflow runs a fixed number of times. Full analysis in Appendix D. Token use is similarly asymmetric (Appendix D): per run, the generation loop consumes about 1.5Minput and 0.8–2.2M output tokens, and the Coder about 5K input and 5–7K output tokens, both on the local open-weight model used by all baselines. The Reasoner, the only component served by an external API, uses about 3K tokens per run, three orders of magnitude fewer. 4.6 AUDITABILITY ANALYSIS 

We evaluate auditability with an LLM-as-a-Judge panel of three models from distinct families (Gemini 3.1 Pro , Claude Opus 4.7 , GPT-5.5 ), scoring the best Scenario 1 heuristics from 1 to 5 on three rubrics: Semantic Grounding (are the variables tied to physical system state?), 

Auditability (how quickly can an operator locate and edit the logic governing processor saturation?), and Simulatability (can the assignment be predicted by hand?). Each (judge, method, rubric) triple is queried five times at temperature 0.7 (details in Appendix F). TRACE is the only method that scores above 1.3 on Semantic Grounding (3.33 vs. 1.00–1.27; Table 3), as its branching logic and penalty factors are tied to predicted processing times and thresholds, whereas the baselines rely on abstract mathematical transformations. On Auditability, it scores 4.67 against 1.33–2.00, since no baseline exposes a per-processor threshold that an operator could tighten. Every judge ranks TRACE first on both rubrics, which mitigates concerns about judge-specific bias, including from the Gemini judge, whose family also serves as TRACE’s Reasoner. With a single heuristic per method, the scores should be read as indicative. Simulatability exposes a trade-off: TRACE’s policy calls the learned predict() surrogate and cannot be evaluated by hand (1.00), whereas ReEvo’s three-line modulo rule can (5.00) but encodes no system property. The surrogate itself is a low-order regression over the task features that can be inspected separately, whereas hashing rules admit no such decomposition. 

# 5 RELATED WORK 

Dynamic resource assignment. Resource assignment is commonly formulated as the Dynamic Job-Shop Scheduling Problem (DJSSP), addressed with hand-crafted heuristics, DRL, and graph-based policies (Liu & Huang, 2023; Zhang et al., 2022). LLM-based AHD has also been applied to job-shop variants: LLMMA couples an LLM with a memetic algorithm for lot-streaming hybrid job shops (Li et al., 2025), SeEvo performs population self-evolution for the DJSSP (Huang et al., 2026a), and recent works target dynamic flexible job shops with evolutionary textual gradients (Huang et al., 2026b) and job shops with preventive maintenance (Liu et al., 2026b). These works typically assume deterministic and known processing times and infinite buffers, which do not hold in the streaming, finite-buffer systems targeted in this work (Sec. 2). 8Preprint 

LLM-based Automatic Heuristic Design. Early genetic-programming approaches (Zhang et al., 2023) evolved tree-structured heuristics within rigid search spaces; LLMs have since enabled the evolution of arbitrary code (Yu & Liu, 2026). FunSearch (Romera-Paredes et al., 2024) established the LLM-driven evolutionary loop, EoH (Liu et al., 2024) introduced structured evolutionary operators, and ReEvo (Ye et al., 2024) added “verbal gradients” derived from the performance history. Subse-quent works employ harmony search (Dat et al., 2025), reinforcement learning (Huang et al., 2025), Monte Carlo Tree Search (Zheng et al., 2025), and niche-based search over language spaces (Hu & Zhang, 2025), while AlphaEvolve (Novikov et al., 2025) extends the paradigm to broad scientific and algorithmic discovery. Recently, MoH meta-learns the heuristic optimizer itself (Shi et al., 2026), EoH-S evolves complementary sets of heuristics (Liu et al., 2026a), and PathWise plans over the space of heuristics with a world model (Gungordu et al., 2026). They are evaluated on combinatorial and black-box optimization benchmarks (Sun et al., 2026; Chen et al., 2025; van Stein et al., 2025). Such advances change how the search proceeds, whereas TRACE changes what the LLM observes ;its Agentic Workflow is thus orthogonal to the choice of evolutionary backbone. Regarding feedback, ReEvo and HSEvo verbalize reflections derived from the fitness history (Ye et al., 2024; Dat et al., 2025), DHEvo co-evolves training data with primal-gap feedback (Zhang et al., 2025), and MLES incorporates multimodal feedback through pre-engineered visual pipelines (Hu et al., 2025). In all these methods, the LLM receives either the fitness, possibly verbalized, or feedback whose content is fixed by the framework designer. To our knowledge, TRACE is the first AHD framework in which an agent decides what to extract from the execution logs of the target system and writes the code that extracts it, including executable surrogate models that the evolved heuristics can call. 

LLM-based design for networked and computing systems. Beyond AlphaEvolve’s improved production data-center scheduler (Novikov et al., 2025), AHD has evolved 5G LDPC decoding functions (Namvar et al., 2026b;a) and routing heuristics that are re-synthesized upon traffic-regime shifts and repaired from verifier traces (Guo et al., 2026), and LLMs have guided virtual network embedding (Pan et al., 2026) and vehicular edge computing heuristics (Huang et al., 2026c). None of them derives knowledge about the unknown system dynamics from execution logs. 

# 6 LIMITATIONS 

First, TRACE’s performance depends on agents capable of deducing latent dynamics and writing valid extraction code, and on execution logs with informative columns. When these are lacking, as in the Llama-3.1-70B runs where the Coder failed to generate valid code to parse the logs and train a surrogate (Appendix E), or when logs lack the relevant fields, the agentic workflow yields no useful knowledge and TRACE degrades gracefully to its scalar-feedback backbone (i.e., EoH), so its worst-case performance is lower-bounded by standard AHD. Second, the one-time discovery cost (roughly 2.5 wall-clock hours; Appendix D) is amortized over the deployment lifetime of the heuristic but non-negligible if hardware changes frequently. Hardware updates, however, need not restart from scratch: seeding the evolutionary loop with previous high-performing heuristics and new platform logs lets the agentic workflow re-derive all hardware-dependent quantities (e.g., per-processor energy profiles, surrogate models) and adapt existing heuristics instead of rediscovering them, substantially reducing compute. Third, for highly complex dynamics, the surrogate regressors needed may exceed the latency budget. However, low-order regressions give accurate approximations in our benchmarks, which are represen-tative of real-world resource-assignment systems (Soualhia et al., 2015; Bader et al., 2024; Schiavo et al., 2024; Lo Schiavo et al., 2024). 

# 7 CONCLUSION 

We presented TRACE, which extends LLM-based Automatic Heuristic Design beyond scalar feed-back: an agentic workflow distills system execution logs into insights and executable surrogate models that guide heuristic evolution. TRACE outperforms state-of-the-art AHD methods on cloud and 5G vRAN scenarios, e.g., cutting energy by 65% relative to the industry standard without losing reliability, and yields more auditable heuristics at under 2% overhead. We show that system logs are thus a valuable, largely untapped source of feedback for AHD. 9Preprint

# B EXPERIMENTAL METHODOLOGY : C LOUD COMPUTING USE CASE 

Simulation Environment. We consider a task feature space of dimensionality d = 5 , where each task 

i is represented by a feature vector xi ∈ [0 , 1] d. The system comprises N heterogeneous processors. To model hardware heterogeneity, each processor n is characterized by a hidden capability vector 

hn ∈ [0 , 1] d. Following the specialized literature, we model the processing time ti,n as the alignment between the task requirements and the processor’s capabilities, i.e., ti,n = x⊤ 

> i

hn (Soualhia et al., 2015; Bader et al., 2024; Rosa et al., 2021); non-linear dynamics are stress-tested in the 5G case study (Sec. 4.4). In this formulation, some processors can be specialized in one or several features, which implies a small value for the corresponding features. Each processor n maintains a finite First-In-First-Out (FIFO) queue with capacity Ln, drawn from [5 , 15] . If a task is assigned to a processor where the queue is full, the task is dropped immediately. 

Task generation. Tasks are generated in discrete-time slots of 1 ms, with the number of tasks per slot drawn from a uniform distribution U [0 , λ ]. We design the distribution such that 90% of tasks are “specialized” (having high magnitude in specific dimensions and low noise elsewhere), while the remaining 10% have uniformly random features. Note that the heuristic observes only the task vector xi, lacking access to the hidden processor vectors {hn}Nn=1 and the processors’ instantaneous queue lengths. The system generates a detailed post-hoc CSV execution log. Each discrete task event records: (i) Arrival context: Timestamp and feature vector xi; (ii) Decision: The selected processor 

n; (iii) Outcome: Processing latency ti,n (if admitted), binary drop status, and arrival queue states. 

Experimental Protocol. We define two evaluation scenarios comprising N = 10 and N = 50 

processors. For each scenario, we evaluate the generated algorithms over a simulation window of 3,000 time steps (3 seconds). Each heuristic is evaluated over three load levels in sequence: Low (λ = 2 ), Medium ( λ = 5 ), and High ( λ = 10 ), so that its cost reflects a variety of operating conditions. Performance is quantified using three metrics: (i) Loss , the probability of task drop; (ii) Delay , the 13 Preprint mean latency for admitted tasks; and (iii) the Cost as defined in Eq. 1. We calibrate the drop penalty 

Γ to enforce a high priority on reliability, setting Γ = 135 for the 10-processor scenario and Γ = 600 

for the 50-processor scenario.

# G REAL -W ORLD CASE STUDY : E NERGY -E FFICIENT 5G V IRTUALIZATION 

G.1 MOTIVATION AND PROBLEM FORMULATION 

To demonstrate the practical utility of TRACE in industrial-grade environments, we instantiate the general resource assignment framework within the domain of 5G virtualized radio access networks (vRAN). This setup grounds our analysis on a real-world use case where the system must consistently satisfy hard time deadlines for signal processing while minimizing the energy toll. In modern 5G architectures, base station (BS) functions are decoupled from proprietary hardware and executed as software processes on general-purpose cloud computing platforms at the edge (Schiavo et al., 2024); see Fig. 8. The computational bottleneck of this pipeline resides in the Physical Layer (PHY) processing—specifically the decoding of uplink user data encapsulated in Transport Blocks (TBs). Upon arrival, raw radio signals must undergo Forward Error Correction (FEC), typically utilizing LDPC decoding algorithms, to recover the original information. This process is highly computationally intensive and subject to hard time deadlines, typically in the 1–3 ms range; failing to decode a TB within this budget results in data loss and compromises industry-grade reliability. Moreover, as 5G networks densify, the energy consumption of these decoding tasks has emerged as a primary operational expenditure (OPEX) and environmental concern for operators. Consequently, it is of paramount importance to schedule appropriate computing resources to 5G wireless processing tasks to minimize the energy footprint while guaranteeing carrier-grade processing deadlines. We model the stream of incoming TBs as a task sequence. Each task i is characterized by a feature vector xi ∈ R3, comprising three physical layer parameters that dictate computational complexity: • Transport Block Size (TBS) : The data volume represented by the total number of bits. Larger TBs typically lead to increased processing latency as the decoding workload scales with data volume. • Modulation and Coding Scheme (MCS) : The spectral efficiency index, indicating the density of the signal constellation. Higher MCS levels are more spectral efficient (carry more bits per signal sample) but may be more compute-intensive depending on the signal quality. • Signal-to-Noise Ratio (SNR) : The quality of the received signal, measured in dBs, that depends on the radio channel. Lower SNR necessitates more iterative convergence steps in the decoding algorithm, non-linearly increasing processing time. An edge computing platform may comprise heterogeneous processing units, including general-purpose CPUs and specialized hardware accelerators (HAs) such as GPUs, ASICs, or FPGAs. To characterize the hardware heterogeneity inherent in this domain, we analyze the experimental data gathered from a production-grade vRAN testbed (Schiavo et al., 2024). The testbed consists of a pool of 16 × Intel Xeon Gold 6240R CPU cores running the Intel FlexRAN library to process signal processing requests, and an NVIDIA V100 GPU utilizing a commercial LDPC driver (NVIDIA Aerial) to accelerate decoding tasks. Fig. 7(a) illustrates the latency-energy trade-offs: CPU processing latency scales linearly with the allocation of bandwidth resource (and so larger TBs) frequently exceeding hard time deadlines for large workloads. In contrast, the GPU leverages massive parallelism to maintain near-constant processing times, effectively absorbing high-demand workloads without saturation. However, this performance advantage incurs a significant energy toll. As shown in Fig. 7(b), the CPU maintains significantly higher energy efficiency compared to the GPU-based HA, particularly for smaller TBs. We further note that these dynamics are governed by the Signal-to-Noise Ratio (SNR). A lower SNR necessitates additional iterative convergence steps in the belief-propagation decoding algorithm implemented by LDPC decodders, non-linearly increasing both processing latency and energy consumption. To address this use case, we adapt the general problem formulation from Sec. 2 to reflect the system constraints of a 5G vRAN. In this context, the optimization objective shifts from raw latency minimization to energy efficiency , subject to a hard processing delay constraint. Latency is treated as a binary feasibility condition rather than a continuous cost. # H PROMPTS 

H.1 DEFINITIONS 

At each generation step i, TRACE synthesizes a Generation Prompt to guide the LLM in producing a new candidate algorithm. This prompt acts as a structured context window, integrating static problem definitions with dynamic environmental insights. It comprises four essential components: 

1. Problem Description: A formal natural language definition of the resource allocation environment, encompassing invariant system parameters (e.g., computing node count N , feature dimensionality d)and the input/output interface required for the algorithm. 

2. System Information: A dynamic textual description of the environment’s latent properties, updated at the start of each epoch. This component encapsulates the Diagnostic Knowledge extracted by the agentic workflow, effectively defining the boundary between known and unknown system dynamics. It includes derived insights (e.g., ”Processor 0 is more efficient with a certain type of tasks”) and inferred constraints, providing the LLM with a grounded inductive bias for optimization. 

3. Example Algorithms: A set of m parent heuristics sampled from the database. To drive improvement, selection is biased towards high-scoring candidates. 

4. Evolutionary Operators: Meta-instructions that define the variation strategy for the current step. Adopting methodologies from recent AHD literature (Liu et al., 2024; Ye et al., 2024), these operators instruct the LLM to perform crossover (recombining logic from parents) or mutation (introducing novel code structures), thereby balancing exploration and exploitation.
