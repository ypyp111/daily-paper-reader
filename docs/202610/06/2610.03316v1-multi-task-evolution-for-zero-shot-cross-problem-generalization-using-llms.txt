ABSTRACT
Designing effective heuristics for diverse combinatorial optimization problems re-
quires substantial expertise and repeated search. Large language models (LLMs)
automate heuristic generation and refinement, but heuristic search typically de-
pends on evaluation feedback from the problem being optimized. Generalizing
to new problem definitions using only source-task feedback therefore remains a
central challenge. We introduce MECo, an LLM-driven multi-task evolutionary
framework for zero-shot cross-problem generalization. MECo maintains task-
conditioned heuristic populations and uses a transfer gap based on cross-task
population performance to guide their interactions. These interactions enable the
transfer and recombination of heuristics. A complementary selection criterion
then constructs a compact heuristic set by rewarding each member’s additional
coverage of source combinations. The selected set is applied to target problems
without further search or adaptation. Experiments on 32 problem variants across
vehicle routing (VRP) and flexible job-shop scheduling (FJSP) show that MECo
achieves the lowest mean costs compared with eight automated heuristic design
(AHD) baselines under the same budgets. On out-of-domain problems, it outper-
forms the strongest baseline in each family. Moreover, integrating the framework
of MECo with different AHD methods improves their ID and OOD performance
in both families, supporting its effectiveness across different methods.

INTRODUCTION
Combinatorial optimization problems (COPs) arise in a wide range of logistics and manufacturing
applications (Toth & Vigo, 2014). Changes in operational requirements can introduce new prob-
lem variants, often requiring existing heuristics to be adapted or redesigned. This process demands
domain expertise and repeated cycles of design and evaluation, making heuristic development a re-
curring cost. Large language models (LLMs) offer a promising way to reduce this burden through
automated heuristic design (AHD) (Liu et al., 2026b). Given a problem description and evalua-
tion feedback, these methods iteratively generate and refine executable heuristics. We distinguish
task-specific AHD, which designs heuristics for each problem independently, from cross-task AHD,
which jointly develops heuristics for multiple problems. Figure 1 compares these design paradigms
alongside our framework.
We define a task as the design of heuristics for a particular optimization problem.
Task-
specific AHD methods have made substantial progress in automating this process. Population-
based evolutionary search combines LLM-driven program generation with fitness-based selec-
tion (Liu et al., 2024b; Romera-Paredes et al., 2024). Reflection further guides program gener-
ation using performance feedback (Ye et al., 2024). Other methods balance exploration and ex-
ploitation through diversity-oriented evolution with harmony-search refinement (Dat et al., 2025)

This creates a potentially large family of related design tasks. If each new task requires a fixed
search budget, the total design cost grows with the number of tasks. Moreover, evaluation data for
new combinations may be unavailable. This motivates designing heuristics using feedback from a
limited set of source tasks and applying them directly to new problems without additional heuristic
search.
To address this challenge, we propose MECo, an LLM-driven framework that uses Multi-task
Evolution through task Combination to enable zero-shot cross-problem generalization. Starting from
source tasks, MECo progressively develops new populations for combined task specifications. Their
offspring inherit and adapt parent heuristics through evolutionary operators designed for cross-task
knowledge transfer. These offspring are evaluated separately on the available datasets, allowing
joint feedback to guide heuristic design for combined problems without accessing their instances.
To guide interactions among the growing collection of populations, a task transfer gap measures how
well the heuristics from one population perform on the sources associated with another. MECo uses
this measure to favor compatible parent tasks while exploring new combinations. Finally, it selects
a small set from all task populations according to the complementary performance of its members
across combinations of sources. Both evolution and set selection rely exclusively on source data,
and the selected programs are applied to target problems without further search or adaptation.
Our contributions are summarized as follows.
• We introduce MECo, a multi-task evolutionary framework that develops complementary
heuristics for zero-shot cross-problem generalization using source task feedback alone.
• We introduce a population-level transfer gap to quantify empirical task compatibility and
guide heuristic transfer between task populations.
• Experiments on 32 variants across vehicle routing (VRP) and flexible job-shop schedul-
ing (FJSP) show lower mean costs on unseen problems than eight AHD baselines under
matched proposal budgets. Integrating the framework with three existing AHD methods
further improves their performance.

2.2
SOURCE-ONLY DESIGN FOR CROSS-PROBLEM GENERALIZATION
We consider source tasks Tsrc and target tasks Ttar whose underlying optimization problems differ
with Tsrc ∩Ttar = ∅. During heuristic design, evaluation feedback is available only from DT for
T ∈Tsrc. Target datasets are kept until testing.
The goal is to obtain a set H ⊆A heuristics that performs well across target problems using only
the feedback from the source tasks. Within each problem family, the heuristics share a decision
representation that permits their application across tasks. Zero-shot evaluation applies the result-
ing set to target problems without further heuristic search or task-specific adaptation. This setting
assesses generalization across out-of-domain problem definitions. Evaluation of new instances of
source problems additionally measures the generalization of the in-domain generalization.

METHOD
3.1
GENERALIZATION THROUGH JOINT TRAINING
Joint source training can yield stronger heuristics for a combined problem than separate source
training. We illustrate this phenomenon in VRP, where O, TW, B, and L label constraint attributes.
Two parent populations evolve on their respective source datasets. An offspring population inherits
their heuristics and evolves using both sources, with the same number of additional LLM-generated
heuristic proposals for each branch. Figure 2 compares the best heuristic from each branch on the
same combined problems and shows that joint source feedback can improve generalization. This
observation motivates exchanging heuristics between task populations.

Evolving Task-Conditioned Heuristics.
Once the parent tasks are chosen, MECo uses their best
heuristics as the initial parents for TC. The LLM receives the parent program or programs required
by its operator, their task descriptions and source scores, and the combined-task description. Later
generations choose parents from the local population and evaluate each proposed heuristic on the
source datasets.
Four prompt-based operators guide this evolution through three forms of crossover and one guided
mutation: (1) c1 performs mechanism composition, combining compatible decision rules from two
parents. (2) c2 performs conflict-resolving crossover, integrating conflicting parent rules through
conditional or hierarchical decisions. (3) c3 performs exploratory crossover, using two parents with
contrasting source scores to propose a distinct decision principle for an under-covered source dimen-
sion. (4) m1 performs transfer-oriented mutation, retaining the parent’s backbone while modifying
a decision mechanism to improve its source performance.
The local population preserves candidates with different source strengths. Candidates are ranked by
nondominated fronts on the constituent dimensions of f(h), with crowding distance favoring less
crowded score vectors within each front (Deb et al., 2002). Comparing their decisions on the same
construction states further prioritizes distinct behaviors (Zhang & Lu, 2026).
After the evolutionary search, successful heuristics from that expansion are selected by JC and
behavioral priority to form the retained population. If TC already exists, its previous and new popu-
lations are merged using the local survival rule. The updated population then becomes available for
future task interactions. Repeating these expansions produces candidate heuristics for progressively
richer task specifications.

EXPERIMENTS
4.1
EXPERIMENTAL SETUP
Problem setup.
We study vehicle routing problem (VRP) and flexible job-shop scheduling prob-
lem (FJSP). The base VRP is the capacitated vehicle routing problem (CVRP), which serves every
customer using depot-to-depot routes subject to vehicle capacity and minimizes total travel distance.
The base FJSP assigns each operation to an eligible machine and sequences operations to minimize
makespan, subject to within-job precedence and machine availability. For VRP, the designed heuris-
tic selects the next customer during route construction. For FJSP, it selects the next operation and its
machine from feasible assignments.
We construct 16 variants per family by activating subsets of 4 optional constraints. VRP uses
open routes (O), backhauls (B), time windows (TW), and route-length limits (L), following multi-
task VRP formulations (Liu et al., 2024a). FJSP uses release dates (R), assembly precedence (A),
sequence-dependent setups (S), and transport lags (T) (Reijnen et al., 2026; Lin et al., 2022; Shen
et al., 2018; Berterottière et al., 2024). Only the four single-constraint tasks provide training datasets.
Testing on larger, unseen instances of these four problems measures in-domain (ID) generalization.
Testing on the 11 combined-constraint problems and the base problem measures out-of-domain
(OOD) generalization. Appendix C specifies the constraint semantics.
Baselines.
We compare eight AHD methods and two classical construction rules per family, orga-
nized into three groups.
(1) Task-specific AHD. EoH (Liu et al., 2024b), ReEvo (Ye et al., 2024), MCTS-AHD (Zheng et al.,
2025), EoH-S (Liu et al., 2026a), MEoH (Yao et al., 2025), and HSEvo (Dat et al., 2025) perform
heuristic search for a given design task.
(2) Cross-task AHD. MoH co-evolves heuristics and optimizers (Shi et al., 2026), while EMO-STA
combines shared search with task-specific adaptation (Gozeten et al., 2026). All methods use the
same four source tasks and problem interfaces.
(3) Classical heuristics. VRP uses nearest-feasible construction and savings-priority construc-
tion (Clarke & Wright, 2012). FJSP uses earliest-completion-time (ECT) dispatch and most-work-
remaining dispatch with ECT machine assignment (MWKR-ECT), following established dispatch-
ing principles (Lei et al., 2022). Appendix D.3 gives the baseline settings and rule definitions.

CROSS-PROBLEM GENERALIZATION
As shown in Table 2, MECo achieves the lowest mean costs on both the source and unseen problems
in each family. Its advantage extends across the all-variant, ID, and OOD aggregates, together with
the lowest average rank and relative gap. Under the shared source-only protocol, MECo therefore
achieves better aggregate performance on unseen problems than the compared AHD methods.
Specifically, on VRP, MoH is the strongest baseline by mean cost in all three groups. MECo lowers
its ID cost from 21.88 to 21.60 and its OOD cost from 22.55 to 22.11. Therefore, the improvement
extends beyond the four problems supplying training feedback. In addition, MECo also has an
average rank of 2.31, compared with 3.97 for the next-best method by rank, HSEvo. Similarly, on
FJSP, MECo lowers the OOD mean from 1487.3 for MoH to 1474.4, alongside a lower ID mean
of 1211.3. Its OOD standard deviation is also smaller, 1.1 compared with 11.9 for MoH, indicating
7


less variation across the repeated searches in this study. The average rank of 1.12 and mean relative
gap of 0.02% place MECo close to the best observed method across the 16 variants.
As shown in Figure 4, both task-specific and cross-task baselines have higher OOD aggregate costs
in both families. Together, these observations support the advantage of MECo on cross-problem
generalization across VRP and FJSP. Appendix E.1 provides more detailed results.

4.3
FRAMEWORK EFFECTIVENESS
We further investigate the effectiveness of MECo’s task-search framework across different heuristic
search methods. For each baseline X, we construct X-MECo by using its native heuristic generation
and population update rules within MECo’s task populations. MECo chooses the interacting tasks
and transfers their parent heuristics to initialize a combined-task population. The baseline then
evolves that population using its own search rules. Thus, EoH-MECo runs EoH within each task

COMPONENT ABLATIONS
We study the importance of task pairing and heuristic evolution operators in MECo by evaluating
five ablation settings against the complete framework. The condition without transfer gap replaces
guided task-pair selection with uniform random sampling, while the remaining four conditions
individually omit mechanism composition, conflict resolution, exploratory crossover, or transfer-
oriented mutation across all evolutionary stages. As shown in Table 4, removing any single com-
ponent degrades overall solution quality, leading to higher mean costs across both problem families
on both ID and OOD tasks. Specifically, omitting transfer gap guidance and transfer-oriented mu-
tation leads to the largest performance drops on VRP. On FJSP, removing exploratory crossover
yields the highest makespan while also introducing substantial run-to-run variance. In addition, full
MECo consistently maintains lower standard deviations than the ablated variants, indicating that the
full pipeline provides more reliable optimization. Together, these results confirm that guided task
pairing and the specialized operators work together to achieve MECo’s strong generalization across
diverse problem domains.

CONCLUSION
This work introduces MECo, an LLM-driven multi-task evolutionary framework for zero-shot cross-
problem generalization. Transfer gaps guide interactions among task populations, enabling heuris-
tics to be adapted and recombined. Source feedback supports both evolution and complementary set
selection, without target evaluations during design. Experiments on VRP and FJSP demonstrate im-
proved ID and OOD performance under a shared design budget. Moreover, integrating MECo with
EoH, ReEvo, and HSEvo consistently improves their performance. Together, these results support
coordinated multi-task search as an effective approach to designing heuristic sets that generalize
beyond their source problems.

RELATED WORK
A.1
TASK-SPECIFIC AUTOMATED HEURISTIC DESIGN
LLM-driven AHD commonly uses evolutionary search to generate and refine executable heuristics
from problem-specific feedback (Romera-Paredes et al., 2024; Liu et al., 2024b; Van Stein & Bäck,
2024). Natural-language descriptions and reflection provide additional guidance for program evo-
lution (Liu et al., 2024b; Ye et al., 2024). Other search strategies include diversity-aware evolution
(Dat et al., 2025), Monte Carlo tree search (Zheng et al., 2025), and neighborhood search (Xie
et al., 2025b). These approaches differ primarily in how they explore the program space and reuse
evaluation feedback.
A complementary direction addresses variation among instances of the same problem. Heuristic-
set evolution (Liu et al., 2026a) and instance specialization through feature-based partitioning or
performance-based clustering (Zhang et al., 2025a; Hu et al., 2026) seek complementary strengths
across instance groups. Multi-objective search additionally considers trade-offs between solution
quality and computational cost (Yao et al., 2025). Applications extend to parameter adaptation and
ruin-operator design within vehicle-routing solvers (Xie et al., 2025a; 2026), as well as algebraic
turbulence-model discovery (Zhang et al., 2025b).
A.2
CROSS-TASK AUTOMATED HEURISTIC DESIGN
Cross-task AHD investigates reusable knowledge beyond an individual design task. Existing ap-
proaches transfer task-agnostic algorithmic templates through hierarchical representations (Liu
et al., 2026c), learn heuristic optimizers through meta-optimization (Shi et al., 2026), or share pro-
gram archives before task-specific adaptation (Gozeten et al., 2026). The reusable knowledge con-
sequently ranges from abstract search principles to executable programs, with downstream feedback
guiding their specialization.
A.3
KNOWLEDGE TRANSFER ACROSS OPTIMIZATION TASKS
Knowledge transfer across optimization tasks has also been studied through learned solvers and
shared search populations. In neural combinatorial optimization, multi-task VRP learning trains a
shared solver across problem definitions and studies zero-shot transfer to unseen constraint combi-
nations (Liu et al., 2024a; Zhou et al., 2026; Chen et al., 2026). Evolutionary multitasking exploits
shared representations and cross-task reproduction, with adaptive transfer mechanisms regulating
exchange as populations develop (Gupta et al., 2015; Bali et al., 2019). The usefulness of such an
exchange motivates studying task relationships. Related work in representation learning character-
izes these relationships through Fisher-information embeddings (Achille et al., 2019) and directed
transfer graphs estimated from predictive performance (Zamir et al., 2018), distinguishing represen-
tational similarity from empirical transfer utility.

This section expands the task interactions, population updates, and heuristic-set selection introduced
in Section 3. We retain the notation TC for a design task, PC for its population, and DTj for a

B.1
SEARCH PROCEDURE
The explored tasks form a directed acyclic graph. Its roots are the single-attribute tasks, and an
interaction between TA and TB produces TA∪B. Eligibility requires both A ⊊A∪B and B ⊊A∪B,
so each parent contributes an attribute absent from the other. Every edge therefore increases the
attribute set. Several parent pairs can reach the same task, allowing its population to incorporate
heuristics developed through different combinations of prior knowledge.
Algorithm 1 summarizes the search under a proposal budget Q. Each source receives an initial
allowance qs, and each expansion receives a local allowance q, with population capacity N. A
completed interaction retires its parent pair while leaving both parent tasks available for other inter-
actions. Repeatedly reached tasks retain a single merged population. Consequently, task exploration
and local evolution share the same budget, and the graph grows according to source feedback.

Within each problem family, programs use a shared constructive decision interface. The current in-

C
TASK DEFINITIONS AND CONSTRAINT SEMANTICS
We address two families of tasks in this paper. Each contains a base problem and four optional
attributes. Active attributes determine the feasibility rules and cost conventions. These models draw
on published problems, while their joint instances and augmentation parameters define the task
families used in this study.
C.1
VRP
The base capacitated vehicle routing problem assigns every customer to exactly one route starting
at a depot. Vehicles have capacity Q, and the objective is total traveled distance. We use the four
attributes considered in multi-task VRP solving by Liu et al. (2024a), with the following load and
route conventions.
Open routes O.
A vehicle may end its route at its final customer. The objective excludes the
return leg to the depot. This convention models deliveries for which the vehicle need not return to
its original dispatch point. It also changes the travel required when checking the remaining route
budget.
Time windows TW.
Service at customer i must start within [ai, bi]. Early arrivals wait until ai,
and departure follows service completion. If t is the departure time from the preceding node and τi
is the travel time to i, service starts at max{t + τi, ai}. Closed routes also respect the depot return
deadline. Time windows represent customer availability and scheduled delivery commitments.
Route-length limits L.
Each route’s total traveled distance is bounded by a prescribed limit. The
return leg counts only for closed routes. This bound models a limited travel allowance, such as a
distance-based operating range, and remains distinct from waiting and service times under TW.
Mixed deliveries and pickups B.
B introduces pickups alongside deliveries and permits their
visits to interleave. A route whose first customer is a pickup departs empty and serves pickups only.
A route beginning with a delivery departs with load Q. Let di be positive for deliveries and negative
for pickups. After visiting customer vk, the load obeys
qk = qk−1 −dvk,
0 ≤qk ≤Q.
(16)
The total delivered quantity and total collected quantity on each route are each bounded by Q. These
conditions remain active when B is combined with O, TW, or L. Customer selection preserves all
applicable conditions, and the resulting routes are checked for coverage and feasibility. The attribute
represents a vehicle sharing capacity between outbound deliveries and inbound collections. The
pickup-first convention separates empty-departure collection routes from routes carrying delivery
loads.
Composition and feasibility.
For a task PC, all attributes in C apply to the same route. For
example, O+TW+B combines open-route accounting, service-window checks, and the mixed-load
trajectory. At each construction step, a customer is available only if it satisfies every active condition.
Capacity and customer coverage remain part of the base problem.
C.2
FLEXIBLE JOB SHOP SCHEDULING
Each job consists of ordered operations. Operation o must be assigned to one eligible machine m
and processed without interruption for pom time units. Operations on the same machine cannot
overlap. The objective is the makespan, the largest operation completion time.
Release dates R.
Each job has a release date known before scheduling. Its operations must respect
this availability time. The constraint represents the arrival of material or a production order. We
specialize the job-arrival setting in Reijnen et al. (2026) to dates available at the start of construction.
18


Assembly precedence A.
A sparse acyclic set of cross-job edges augments the within-job op-
eration chains. An operation can begin only after all its predecessors finish. Such edges model
components that must be produced before a downstream assembly or dependent processing step.
We draw on the coupled-job setting of Lin et al. (2022) and generate additional predecessor graphs
for our instances.
Sequence-dependent setups S.
The setup duration depends on the machine and the families of
two consecutive operations on that machine. This models changeovers such as tool replacement or
cleaning. We follow the sequence-dependent setup semantics studied by Shen et al. (2018). The
machine is unavailable for processing during its setup, and its first operation uses an initial setup
duration.
Transportation delays T.
Successive operations of a job incur a deterministic delay when as-
signed to different machines. This represents the time required to move a part between workstations.
We adapt the transportation setting of Berterottière et al. (2024) to fixed machine-to-machine lags.
The present model imposes no competition for a finite fleet of transport vehicles.

selection. The entries report means and sample standard deviations over three searches. Average

achieve the lowest cost on either target, its costs remain close to the best observed values and it
achieves the best average rank. Moreover, MECo uses half as many additional proposals as the

We also study joint heuristic design across TSP, base VRP, and FJSP. Each method shares an al-

MECo achieves lower TSP and VRP costs than EMO-STA and MoH at both test sizes. It also
improves over EMO-STA on FJSP, where MoH performs best. These results extend the evaluation of
MECo from constraint variants within a family to joint design across different constructive problems.
The experiment concerns the participating tasks, rather than zero-shot transfer to an unseen problem

F.3
GENERATION INSTRUCTIONS
Each proposal uses one of the following instructions together with its selected parents and search
context.
33


Mechanism composition c1
Identify one concrete decision mechanism in each parent (for example a ranking
signal, look-ahead, or route-ending rule). Create a child that composes only
compatible mechanisms. Do not paste two complete score functions together; explain
the composed mechanism briefly in the algorithm description.
Conflict resolution c2
Identify a concrete conflict between the decision biases of Parent A and Parent B.
Create a compact conditional or hierarchical rule that resolves the conflict from
the documented runtime state. The result must be one coherent heuristic, not an
average of two arbitrary scores.
Exploratory crossover c3
The parents occupy different regions of the measured root-performance Pareto set.
Design a coherent candidate that improves the under-covered target dimension named
in the search context using a genuinely different decision principle or look-ahead
structure. Do not diversify by renaming variables or perturbing constants.
The mutation instruction below uses one parent and its source evaluation.
Single-parent mutation m1
Keep the parent algorithm as the backbone. Use the task description and source
evaluation to identify a decision mechanism to improve. Revise that mechanism while
preserving the parent’s useful structure and the documented function interface.
