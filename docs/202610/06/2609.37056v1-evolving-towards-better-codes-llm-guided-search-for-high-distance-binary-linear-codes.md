## 摘要
由大语言模型（LLM）驱动的演化程序搜索已在组合数学及其他领域的开放问题中产生了破纪录的构造。我们将这一方法应用于一个长期存在的问题：改进二进制线性码的已知最佳界。基于 EvoTune 演化框架和 ShinkaEvolve 代码库，我们提出 LinCodeEvolve，它让码构造程序在精确最小距离评估器下进行演化。一个策略循环结合了多样性驱动的搜索与专家监督：当进展停滞时，使用新策略来重新引导搜索。LinCodeEvolve 发现了七个破纪录的码，$[172,21,66]$、$[173,20,68]$、$[176,21,68]$、$[181,21,70]$、$[184,21,72]$、$[189,22,72]$ 和 $[200,21,77]$，其中六个具有简洁的准循环描述。借助标准的码修改技术，它们改进了表格中的 $22$ 个条目。每个码都通过穷举枚举得到验证。这些结果表明，LLM 引导的搜索可以帮助找到更优的码，并补充编码理论中的现有方法。

## Abstract
Evolutionary program search driven by large language models (LLMs) has produced record-breaking constructions for open problems in combinatorics and beyond. We apply this approach to the longstanding problem of improving the best-known bounds for binary linear codes. Building on the EvoTune evolutionary framework and the ShinkaEvolve codebase, we introduce LinCodeEvolve, which evolves code-construction programs against an exact minimum-distance evaluator. A strategy loop combines diversity-driven search and expert supervision: when progress plateaus, new strategies are used to redirect the search. LinCodeEvolve discovers seven record-breaking codes, $[172,21,66]$, $[173,20,68]$, $[176,21,68]$, $[181,21,70]$, $[184,21,72]$, $[189,22,72]$ and $[200,21,77]$, six of which have concise quasi-cyclic descriptions. With standard code modification techniques, they improve $22$ entries of the tables. Every code is verified by exhaustive enumeration. These results suggest that LLM-guided search can help find improved codes and complement existing methods in coding theory.

# 论文总结：LinCodeEvolve——LLM 引导的高距离二进制线性码搜索

## 1. 核心问题与整体含义

- **研究背景**：二进制线性码 $[n,k,d]$ 的最小距离 $d$ 决定其最坏情况纠错能力（可纠正 $\lfloor(d-1)/2\rfloor$ 个错误），并直接进入二进制对称信道下最大似然译码的块错误概率界。
- **核心矛盾**：
  - Gilbert–Varshamov（GV）界只保证存在性，而**显式构造**在特定 $(n,k)$ 上可以超越 GV 界，这些构造被记录在 Grassl 的 CodeTables 中。
  - 改进表格下界要求**严格的精确距离认证**，而计算最小距离是 NP-hard 问题；随机搜索（如基于信息集译码的方法）只能给出上界，找不到低重量码字并不能证明其不存在。
- **整体含义**：论文把「码构造」视为自动程序发现的天然场景——构造可执行、输出可评估、评估结果可反哺下一次提案。作者将 LLM 驱动的演化程序搜索（FunSearch / AlphaEvolve / EvoTune / ShinkaEvolve 一脉）迁移到编码理论，目标是系统性地改进**一般二进制线性码**的已知下界，而非仅针对某一特殊族。

## 2. 方法论：LinCodeEvolve

### 2.1 核心思想

- 沿用 EvoTune 的演化搜索回路与 ShinkaEvolve 的执行基础设施（岛屿模型、迁移、新颖性评判、提示演化、UCB1 风格模型选择），在其上叠加面向码构造的组件；**LLM 参数在整个搜索过程中保持固定**。
- 三个动机性观察：
  1. 最小距离是整数值、反馈粒度粗，需引入次级指标；
  2. 模型常直接返回父代矩阵，必须识别「复制」；
  3. 进展往往需要**切换构造族**，因此需要代数工具与历史路线证据。

### 2.2 五大组件

- **Agent 团队**：
  - **Discover**：三次连续模型调用——*oracle* 诊断当前码并建议移动方向；*strategist* 比较构造路线、校验参数算术、输出结构化计划（路线、移动、修改父代还是重开、接受规则、停止条件）；*implementer* 把计划翻译为可调用 Toolkit 的程序。
  - **Invent**：不使用 Toolkit，先描述表示、移动、验证步骤与停止条件，再从底层操作实现。
- **Toolkit**：87 个手写函数（模拟退火、遗传种群搜索、循环码/BCH 父码、Construction X、准循环/准扭矩阵、最小重量码字修复等），由 6 个「family core」按构造类别分组，在截止时间内返回最佳候选。
- **评估与搜索反馈**：对返回矩阵做全重量分布精确计算，适应度为**字典序 $(d, -A_d)$**——优先更大最小距离，其次更少的重量为 $d$ 的码字（shell）。
- **专用岛屿与构造初始化**：初始 8 个种群，每岛携带一种构造族提示（扩域代数码、稀疏图校验设计、准循环多项式矩阵等）；其中**冷启动岛**直接由 $(n,k)$ 构造，**发明岛**只用 invent 算子。每 6 代迁移，最优程序保留；若 6 代未改进则从归档程序播种新岛。
- **精确验证与人类输入**：程序自述不能改变分数；人类通过共享文件注入目标、warm start、注释、证书，并可暂停—修复—恢复。

### 2.3 关键机制细节

- **适应度的概率意义**：二进制对称信道下未检测错误概率
  $$P_{\text{err}}(C;p)=\sum_{i=1}^{n}A_i p^i(1-p)^{n-i},$$
  小 $p$ 时由首项 $A_d p^d(1-p)^{n-d}$ 主导，故最小化 $A_d$ 直接降低未检测错误概率。
- **Generation 0 初始化**：先对设计码、准循环码、代数码等组合做廉价距离估计排序，再用 SageMath 中的 Brouwer–Zimmermann 算法精确评估，选最小距离最大者（$A_d$ 作次级筛选）。目标是选出一个**超过 GV 界**的强种子。
- **归档与淘汰**：归档最多 96 个程序，**每个不同行空间只保留一个**；新码有空间即加入，满则按保持小构造族代表性的规则替换；已在归档中的码不重复加入。
- **提案检查与失败处理**：策略计划不完整可补一次，仍不完整则丢弃；执行前拒绝「仅包装单个 Toolkit 策略」「缺少必需头部」「重实现穷举枚举」的程序；新颖性评判拒绝与父代几乎相同的程序。运行超时/崩溃/输出非法者按「返回父代未变」计分，不进归档，且在已有程序达到距离下限后不再作为父代。
- **算子选择**：继承的 diff / full / cross 算子与 discover / invent 共同采样，概率依父代距离与近期结果自适应；当父代低于距离下限且近期反复返回同一码时，加大 invent 权重。

## 6. 主要结论与发现

- **7 个破纪录码**（相对 2026-09-25 CodeTables 快照）：
  - $[172,21,66]$（+2）、$[173,20,68]$（+1）、$[176,21,68]$（+2）、$[181,21,70]$（+2）、$[184,21,72]$（+3）、$[189,22,72]$（+1）、$[200,21,77]$（+1）。
  - 前五个来自长度 170 的 index-2 准循环父码（块长 85）；$[189,22,72]$ 为块长 63 的 index-3 准循环码；$[200,21,77]$ 由已列出的 $[240,21,104]$ 二进制 Goppa 构造打孔得到。
- **6 个具有简洁准循环描述**，可复现性强；结合标准修改技术共**改进 22 个码表条目**（增益最高 3）。
- **结构优势**：还能找到匹配现有界但描述简洁的码（如纯双循环 $[50,25,10]$）；在 $(200,21)$ 上产生重量分布更优的等价距离码（更小 shell，奇偶扩展后同样更优）。
- **方法定位**：LLM 引导搜索可作为编码理论现有方法（准循环/准扭搜索、二次构造、对称群方法）的补充；框架同样适用于 $q$ 元码（但精确评估代价按 $q^k$ 增长，可行维数相应更小），也可限定在结构化族内寻找族内最优码。

## 7. 优点

- **提案与验证严格分离**：只有精确计算（全重量分布/穷举）能决定适应度，程序自述无法影响分数，杜绝了「LLM 自评」的不可靠性。
- **适应度设计有理论依据**：用 $(d, -A_d)$ 字典序，既提供比单一整数 $d$ 更细的梯度，又直接对应未检测错误概率的首项，具有实际编码意义。
- **人机协同的合理分工**：人类提供数论直觉（$x^{85}-1$ 的分解、维数算术）与平台期分析，机器负责在高维离散空间中搜索与验证，二者互补。
- **工程细节扎实**：区分 discover / invent 两条提案路径、按构造族划分岛屿、冷启动岛与发明岛、归档按不同行空间去重、失败程序降级处理
