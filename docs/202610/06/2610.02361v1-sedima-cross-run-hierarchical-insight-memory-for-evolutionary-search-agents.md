## 摘要
大语言模型（LLM）驱动的进化搜索是一种用于自动程序与算法发现的有力范式，但现有系统大多无记忆：每次运行都从头探索，因此智能体会反复重新发现相同的改进，并再次遭遇相同的死胡同。我们提出 SEDIMA，一种面向进化搜索智能体的持久分层洞察记忆。SEDIMA 将原始轨迹蒸馏为自然语言洞察，使用注意力加权质心按语义相似度对其进行聚类，并检索相关指导以条件化未来的变异，从而在多次运行和多个问题之间（而非单条轨迹内）积累可迁移知识。作为一个即插即用模块，且不修改搜索算子，SEDIMA 在固定评估 100 个候选的预算下，将 AlgoTune 上的平均最终性能提升 5.5%，在 ALE-Bench LITE 上提升 6.6%。在 OpenEvolve 下，SEDIMA 在五个所评估的主干模型上平均需要少 32.3% 的迭代次数即可达到基线最佳性能。

## Abstract
Large language model (LLM)-driven evolutionary search is a powerful paradigm for automated program and algorithm discovery, yet existing systems are largely memoryless: each run explores from scratch, so agents repeatedly rediscover the same improvements and re-encounter the same dead ends. We introduce SEDIMA, a persistent hierarchical insight memory for evolutionary search agents. SEDIMA distills raw traces into natural-language insights, clusters them by semantic similarity using attention-weighted centroids, and retrieves relevant guidance to condition future mutations, accumulating transferable knowledge across runs and problems rather than within a single trajectory. As a drop-in module that leaves the search operators unmodified, SEDIMA improves average final performance by 5.5% on AlgoTune and 6.6% on ALE-Bench LITE under a fixed budget of 100 evaluated candidates. Under OpenEvolve, SEDIMA requires 32.3% fewer iterations on average to reach baseline-best performance across the five evaluated backbones.

# SEDIMA 论文总结

## 1. 核心问题与整体含义

- **研究背景**：LLM 已从一次性代码生成器演变为迭代式搜索算子，广泛用于数学发现、算法设计与启发式合成。OpenEvolve、ShinkaEvolve、LLM4AD 等框架使这一范式更易用。
- **核心问题**：现有 LLM 驱动进化搜索系统基本是“无记忆”的：每次运行都从零开始，运行结束后丢弃成功与失败背后的推理。这导致两类浪费：
  - **跨运行浪费**：新任务上重复发现已有改进，重新探索已知无效方向。
  - **单运行内不稳定**：搜索轨迹波动大，智能体反复提出、遗忘、再提出局部有用编辑，缺少持久信号巩固有效经验。
- **已有工作的不足**：ReEvo、LoongFlow、DeltaEvolve 等虽引入反思或洞察，但记忆仍局限于单条进化轨迹，运行结束即重置；CORAL、PRISM 虽持久，但将搜索改造成长期多智能体系统。
- **整体含义**：SEDIMA 提出一种**持久、分层、跨运行与跨问题的洞察记忆**，作为即插即用模块，不修改搜索算子，仅在“评估后写入”和“变异前读取”两个接口介入，从而积累可迁移知识。

## 2. 方法论

### 核心思想

- 将原始进化轨迹蒸馏为自然语言洞察，按语义相似度聚类，并在未来变异前检索相关指导注入提示词。
- 记忆的关键特征是：**跨运行与跨问题持久化**；检索基于**语义内容**而非**谱系关系**，因此经验可从弱相关任务迁移。
- 与搜索逻辑解耦：选择、种群管理、评估、变异算子均不变。

### 三层记忆结构

- **Level 1：原始轨迹**
  - 每次评估后存储：步索引、父代与子代适应度、适应度差、事件来源、原始评估报告。
  - 不做解释，作为高层记忆的证据，支持检索结果回溯到具体评估事件。
- **Level 2：蒸馏洞察**
  - 用 LLM 将每条轨迹转成紧凑自然语言洞察，并链接回 Level 1 证据。
  - **问题级洞察**：初始评估时生成，描述主要算法或架构瓶颈。
  - **变更级洞察**：每次父代–子代评估生成，描述修改类型与观察到的性能影响；抽象掉实现细节，保留缓存、剪枝、向量化、数据结构修改、减少冗余计算等可复用经验。
  - 每条洞察被嵌入，用于语义组织与检索。
- **Level 3：语义聚类**
  - 新洞察与最近簇代表计算余弦相似度；若超过阈值则加入该簇，否则新建簇。
  - 簇代表随成员增加而刷新；可选 LLM 总结捕捉反复出现的优化模式。
  - **注意力加权质心**：不是简单均值，而是给语义中心、原型性高的洞察更大权重。
    - 成员语义中心性：\(s_i = \frac{1}{n-1}\sum_{j\ne i}\cos(e_i,e_j)\)
    - 注意力权重：\(w_i = \frac{\exp(s_i/\tau)}{\sum_j \exp(s_j/\tau)}\)
    - 簇代表：\(c = \sum_i w_i e_i\)
    - 温度 \(\tau\) 越低越强调原型；越高越接近均值池化。

### 检索与注入

- 变异前，将当前程序及问题嵌入为查询。
- 按簇相似度排序，保留超过阈值的 top \(K_c\) 个簇；每个簇内按洞察相似度选 top \(K_i\) 条洞察。
- 保留簇级与洞察级相似度；每条洞察可选链接最多 2 条 Level 1 轨迹。
- LLM 将检索证据合成 3 条具体建议，插入 diff 或全重写提示词，不改 harness 逻辑。
- 若没有簇超过阈值，回退到原始变异提示词。
- 检索受固定簇数、洞察数和提示词长度限制，因此上下文成本不随记忆总量增长。

### 关键超参数与配置

- 聚类阈值 \(\tau_{cluster}=0.8\)，检索阈值 \(\tau_{ret}=0.6\)，质心温度 \(\tau=0.1\)。
- 检索 \(K_c=3\) 个簇，每簇 \(K_i=3\) 条洞察，证据总预算 2,500 tokens。
- 变异温度 0.7；蒸馏、簇总结、建议合成温度 0.2。
- 嵌入模型固定为 Qwen-Embedding-4B。
- 记忆用不相交问题构建，确保评估问题本身不贡献到用于解决它的记忆中；运行时在线更新并持久化到磁盘。

## 3. 实验设计

- **模型 Backbone**：GPT-5.4、DeepSeek V4 Pro、Gemini 3 Pro、Qwen 3.7 Max、Qwen 3 Coder。
- **预算与协议**：
  - 每次运行最多 100 个进化步，每步生成并评估一个子代。
